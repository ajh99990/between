# Between 本机角色聊天与管理控制台

这是独立角色引擎上的可运行应用原型。聊天入口 `/`，管理员入口 `/admin`；只监听 `127.0.0.1`，不发布、不部署。核心继续调用裁出的 SillyTavern 原实现，不把演示回复当作真实模型效果。

## 启动

Node.js 24+。在本源码包的 `engine` 目录：

```bash
npm ci --omit=dev
npm run start:demo -- --data /tmp/between-app-demo --port 8787
```

浏览器访问同一台机器上的 `http://127.0.0.1:8787`。云容器的 loopback 地址不能直接当成用户设备可访问的预览链接。

演示模式完全本地：合成角色、合成模型流、测试图片、测试音频和合成 ASR/Caption。图片生成时合成上游返回英文描述，以满足原 ST 图片提示词清洗器；这不是模型能力测试。

启用后台时由操作者提供至少12字符的口令，没有默认密码：

```bash
read -rsp '管理员口令：' between_admin_password
printf '%s' "$between_admin_password" | node app/server.mjs --demo --data /tmp/between-app-demo --admin-password-stdin
unset between_admin_password
```

口令不写磁盘；后台登录令牌只在服务进程内保留，最长8小时，重启需要重新登录。不要把真实口令写在命令行参数、源码或报告里。管理员页面自身可打开，但所有后台数据和操作都要求服务端管理员认证；普通聊天用户不能调用。

## 真实模型

去掉 `--demo`，由宿主在启动进程中提供：

- `BETWEEN_MODEL_URL`：OpenAI Chat Completion 兼容根地址，例如末尾 `/v1`；服务会追加 `/chat/completions`。只允许 HTTPS 或本机 HTTP，不接受 URL 用户信息、查询串、片段。
- `BETWEEN_MODEL_NAME`：模型名称。未提供时优先使用后台保存的设置，再回退 `gpt-4o-mini`。
- `BETWEEN_MODEL_KEY`：可选服务端运行时凭据。应用不读 `.env`，不在 UI 显示或录入、不写配置/审计，不把错误响应原文回传浏览器。

后台能改根地址和模型名。已有运行时凭据时禁止跨 origin 切换，需操作者重新启动配置；环境显式设置覆盖磁盘设置。更新地址不主动测试收费模型，下一次用户生成才发请求。连接“已配置”不等于“已验证”。

**计数器仍固定为原先回归过的 `gpt-4o-mini`。更换模型仅替换出站模型名，token预算不保证与别的模型精确一致。** 本轮没有可用真实连接配置，未请求外部模型、未验证真实模型自然度。

真实语音/图片扩展继续保留在引擎模块；本应用默认真实连接只开放文本。宿主可通过 `createApp({mediaConfig,pipeline,rawImage,asrModel,...})` 注入已安装的本地媒体适配器；详见原 `README.zh-CN.md`。不自动下载模型，不配置新付费服务，不宣称实时双工语音已经实现。

## 新增：管理员管理的 ChatGPT 套餐后端

按最新选择，使用独立套餐兼容服务统一管理一份独立 Between 授权及刷新，业务用户/角色/会话保持隔离。默认关闭；管理员在「提示词与模型」明确启用，所有该应用用户共用这份额度，不要求各自登录。没有隐式计费回退，多人托管使用的官方适用性未确认。真实 OAuth 尚未接入或执行，填写模型名不能代替授权。详见 [套餐接入说明](CHATGPT-PLAN.zh-CN.md)。

## 使用与范围

聊天：选角色 → 设置称呼、Persona及可选角色描述覆盖 → 开始会话 → 输入消息。支持流式显示、停止、失败后幂等重试、刷新与正常重启恢复。演示模式还可选本地 PNG/JPEG/WebP、WAV，使用语音转写、朗读和图片生成。附件上限8MB；拒绝外链媒体，聊天文本用 `textContent` 显示，不解释 HTML。

后台：

1. 角色卡：名称、标签、简介、系统提示、描述、开场白、示例、默认 Persona；绑定多本世界书。
2. 世界书：独立可复用资源。合成书为单条，导入社区书保留完整多条及条件；扫描深度4、WI预算25%、递归开启。只开放四张固定校验卡的导入，未开放任意上传或全部高级字段。删除书会解除新会话绑定，不改已有快照。
3. 预设/模型：上下文预算、回复上限、temperature、示例优先、历史后指令、模型连接。
4. 会话/任务：查看元数据、停止生成、确认删除会话。不读取聊天正文来做遥测。
5. 用户/全局：匿名浏览器用户停用/恢复；关闭新用户；暂停新生成。停用会中止该用户任务；暂停开关不自动中止已运行任务。
6. 诊断/素材：最近200条本进程操作记录、Langfuse明确“未接入”、社区候选目录。审计会重启清空，不是不可篡改生产审计。

角色/世界书/预设变更仅影响新会话。模型连接变更影响之后发出的请求。角色自带旧 `world/keys` 字段仅作为迁移兼容数据，实际快照只从独立世界书绑定构建，避免重复注入。配置采用版本检查与串行写入；慢上传不占全局修改锁。

世界书最终纳入条目诊断尚未接出；不展示猜测的激活列表。关键词匹配不等于最终预算后纳入。

| 晚孤市 | 4 | 多NPC口癖、两条常驻 |
| 霍聿深 | 9 | 二级关键词、selective与60–90概率 |

四张均实际带 `character_book`，不是三张。导入直接复用固定ST的 `convertCharacterBook` 与原默认定义，保留二级条件、概率、排序等参数，拆成一本独立书并仅绑定一次；不把原内嵌书再次交给引擎。每本可在世界书页展开编辑条目核心字段，来源归因不可从已有资源中剥离。移除角色但保留书后，再导入会明确拒绝ID碰撞，不覆盖或悄悄复用旧书。

保留原文，包括HTML；浏览器显示为纯文本，不解释HTML/CSS/脚本，不自动加载外链。只使用主开场，备用开场保存在原始文件但UI未开放选择。用户Persona由使用者设置，应用全局历史后指令另行追加。以上是明确的适配差异，并非完整ST视觉兼容。

原始Git字节与父研究SHA相差恰好一个末尾换行，四卡及许可均验证 `SHA256(raw + LF)` 等于父清单；交付保存原始Git字节并同时记录两组SHA。仓库21 stars/1fork仅为父调研热度快照，小众候选而非“热门单卡”。静态内容质量与热度分列，合成回归不代表真实模型自然度。

原Library包下载通道曾被代理隧道403拒绝；没有改代理或重试绕过。此版使用用户单独授权、正常可读的作者公开仓库。该通道历史故障不再阻塞素材集成。

## 数据与安全边界

每个浏览器得到不可猜测 HttpOnly、SameSite=Strict cookie；磁盘索引只保存令牌哈希。用户标识由服务端产生，租户由宿主固定为 `local`。底层按 tenant/user/conversation 分开保存；用户只能访问自己的会话。所有写请求检查 Origin，已认证写请求还检查 CSRF；Host仅允许本机地址。后台删除/停用/全局修改有作用范围与确认。

这是单进程、本机可信宿主原型，不是生产账号/SSO或多租户运营系统。数据目录包含聊天和必要的会话身份材料，需由操作者保管。正常重启恢复已提交历史；底层聊天提交有原引擎原子写与同步语义，应用配置/用户索引为原子替换但未承诺断电级持久性。进程强制杀死后可能留下引擎 `.owner` 锁，按原引擎恢复流程核验旧进程已死后处理，不能盲删锁。

按 Ctrl+C 退出会中止未完成任务并关闭监听。删除本服务会话不承诺删除外部模型/媒体服务已保留的请求或输出。
