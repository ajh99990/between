# 日常聊天反面案例说明

日期：2026-10-19。状态：第一版候选提示词，经过文字与来源审查，尚未通过真实模型验证。

可直接读取的正文是 [普通中文聊天反面案例 v0.1](../experiments/conversation-comparison/prompts/普通中文聊天反面案例-v0.1.md)。该文件全文是供后续实验使用的独立提示词模块；本说明、来源表和开发记录不发送给聊天模型。

## 本轮写了什么

用户明确授权开始编写以具体反面案例为核心的提示词。本模块由本项目新写，借鉴公开讨论中指出的失误，不是任何上游核心提示词的摘抄、改写或缩略版。

十个案例都包含前提、用户消息、不合适的回复、具体问题与允许的回应范围。N04 保留连续多轮，以展示单句看似体贴、累积后持续管人的问题；N02、N04 各含较轻的短句变体，避免只教会模型避开夸张诗句。少量普通回应仅用于说明可行方向，不设唯一标准答案。末尾另给求建议、求安慰和确有情感来历的边界情境，避免把纠正变成另一种冷淡模板。

所有示例对话均为本轮为了教学新编的情境。N01 参考英文社区个案作中文情境重构；其余也不是社区用户原始聊天、模型实测输出或项目真实聊天记录。案例中的字面措辞不具有“黑名单”地位。没有复制私有聊天数据或完整上游提示词。

## 与现有提示词及运行入口的关系

当前 `maibot/`、`xiyu/` 的原文、许可证、来源清单和 hash 不变；已有 `profiles.mjs`、`run.mjs` 和正式角色引擎没有加载这个文件。历史三组对比仍是原文基线，不能把其结果当作这版新提示词的验证。

本模块先独立保存，暂不与两份上游核心规则叠加。后续若决定组合，需要先列出关系设定、安慰要求、发言频率等冲突，保留原文并单独记录新增模块和实际注入顺序；不能借“胶水”名义暗中覆盖上游规则。若独立测试本模块，也要记录宿主另外提供的人设和消息格式，不能声称只有本文件在影响输出。

## 下一轮怎样检验

本轮只有提示词编写和静态检查，没有运行真实模型，也没有据此修改后台或用户数据。

后续实验至少分开检查以下几件事：

1. 在新的独立会话中使用不同于正文的新情境，例如小物件、小抱怨、普通决定；看模型是否理解问题，而非背出案例答案。
2. 多轮覆盖“继续聊”“只确认”“明确结束”，尤其留意关心、建议和提问是否每轮换个形式继续出现。
3. 另测明确求助、寻求安慰、真实情感来历及请求长一点的解释，检查是否矫枉过正。
4. 记录具体输入、实际输出、完整配置与本模块 hash；把词汇、强行升华、交流姿态和事实编造分别判断，不用禁词数量或回复长度替代人的阅读。
5. 测试材料不得进入日常角色、默认内容或真实用户目录；模型请求和聊天证据仍保存在仓库外私有实验目录。未经相应授权不调用模型。

SillyTavern 文档提醒历史本身会影响风格，因此不能只在已被旧风格带偏的会话里加新模块，就宣布模块有效或无效。[^st] TICL 为“失败样例加具体解释”提供相邻研究依据，但评估的是英文个性化写作；它没有验证这里的中文聊天案例。[^ticl]

## 本轮检查与修订

- 文字审查修正 N02 中可能被理解成期待落空的用户句，避免分析先替对方确定情绪；N10 标题与说明改为案例确实出现的过去和象征意义。N02、N04 增加轻微短句变体。
- 十个编号、每个情境的必要部分、来源表、本地链接与脚注通过一致性检查。
- 执行 `node experiments/conversation-comparison/offline-test.mjs` 通过，核对上游原文资源、宿主分离、传输内容及只读复查限制；模型调用数为零。这项检查保护已有基线，不检验新模块的语言效果。
- 仅提示词和文档变更，没有界面或业务代码改动。本轮未做真实模型测试，效果仍待用户阅读及后续对话实验判断。
