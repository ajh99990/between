# Observation boundary: implemented and remaining

The application keeps business truth in SQLite. `ObservationSink.emit` is a synchronous bounded handoff, not a network operation. Throw/drop/full outcomes increment per-execution `observation_gaps`; they do not change role output, rerun the host, or replay business writes. Gap persistence failure has an independent in-process counter. `accepted` means handed to the sink, never Langfuse ingested. The production broker currently uses disabled observations; no platform success is claimed.

`normalize.ts` is a pure privacy/compatibility layer. Default export removes content and opaque content references. Explicit synthetic capture has byte bounds, key/value redaction, field status, multiple/system-only input preservation, and unknown-part preservation. Provider output is labelled raw provider events, never fabricated text. Native trace/span identifiers remain native; all-zero/unmatched fields are not connected by timing. Product identity remains separate. Usage is not guessed and cost is not generated. No second trace database/event bus exists.

The candidate collector configuration targets [official otelcol-contrib 0.162.0](https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.162.0). It uses the mature persistent exporter queue via file_storage, byte capacity 100 MiB, overflow rejection, and bounded retry. These settings follow [exporterhelper](https://github.com/open-telemetry/opentelemetry-collector/blob/main/exporter/exporterhelper/README.md). A 24h retry budget is NOT proof of a 24h absolute retention deadline across queue wait/restart. Physical queue disk usage is NOT necessarily identical to the payload byte budget. Retention/compaction and shutdown tests remain required; configuration is a candidate, not a passed R3.2 gate.

[Langfuse's native OTLP route](https://langfuse.com/integrations/native/opentelemetry) accepts HTTP/protobuf or HTTP/JSON; the v4 ingestion header is explicit. Credentials are supplied through an approved runtime secret mechanism, never embedded here. No endpoint or credentials are assumed. Only redacted data may reach a persistent queue.

The [pinned Langfuse 4.50.0 stack](https://github.com/langfuse/langfuse/blob/v4.50.0/docker-compose.yml) requires web/worker and storage services. This sandbox currently has no Docker, Podman, collector, PostgreSQL, Redis or ClickHouse executables. Those absences alone do not prove deployment impossible. Existing listener/browser-localhost denials still apply; no alternative tunnel, remote deployment, credential transfer or security change was attempted. Current safe work covers contracts and synthetic fault handoff, not HTTP ingestion, restart persistence, API readback or original Langfuse UI.

Remaining: pin collector artifact hash and validate config offline; wire authorized native OTel + business span exporter; add platform-confirmed acknowledgments to independent gap records; execute 429/5xx/disconnect/full/restart/replay/expiry against the permitted stack; prove 24h physical retention; benchmark the specified 1000-call profile and p99 overhead; verify API+DB+UI before claiming R3/R5.

Application content reads now use Linux O_NOFOLLOW, descriptor-path identity under the controlled root, regular-file/single-link checks, bounded bytes, and stable before/after descriptor metadata. Skill and character snapshots are consumed from verified bytes. The MCP receives the character bytes plus SHA256 and validates them before opening the business store; it no longer reopens a character file path. Initialization-to-read leaf/parent symlink replacement and a real stdio MCP cross-process snapshot test are included. Non-Linux has no weaker fallback.

This does not constrain another same-UID process arbitrarily replacing trusted executable JavaScript or native dependencies between verification and OS load. Bubblewrap 0.12.0 is installed, but a stricter read-only/no-network `/usr/bin/true` probe failed with `Failed to create NETLINK_ROUTE socket: Operation not permitted` (exit 1). No alternate flags, elevated capabilities, tunnel or sandbox bypass were tried. Therefore the content-read component can be verified independently, while a complete OS-isolation R1.3 claim remains blocked. This product does not claim to protect secrets from the machine administrator.
