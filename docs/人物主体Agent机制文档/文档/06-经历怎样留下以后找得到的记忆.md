# 经历怎样留下以后找得到的记忆

机制说明 · 依据 Between 固定版本 `c5fddc8d3b3ae81b77d41cba4cede78286e8dd0d` 的待实施设计。

沿用甲发来“今天有点累”的例子。这一篇再增加一条已查看的消息：甲解释，今天的会开得很久，自己周一通常都有周会。

过了一天，人物又和甲聊天。昨天那句话仍然可以查到，但此刻需要使用的内容已经不同：她可以记得甲有周会这个习惯，也可以知道他昨天说会议开得久；要了解他现在在做什么，还需要新的依据。

记忆机制处理的就是这段连接：**从已经接触的材料中选出以后值得取用的部分，连同来源和适用时间保存，再在需要时找回来。** 保存过消息、整理出记忆、这次模型实际读到记忆，是相接的三个环节。[^1]

## 从原话中选出值得保留的内容

前面已经保存了甲的来信，也记录了它何时实际提供给人物模型。现在，系统可以根据这份已查看的材料发起提取任务。任务携带来源 ID，提取模型据此提出值得记住的候选。

在本例里，可以提出两个不同的候选：甲说自己周一通常开周会；甲说今天那场会议开得很久。前者是对一个习惯的认识，后者是一件有具体时间的事情。服务接到候选后，检查它引用的消息是否允许读取、来源是否存在，以及候选表达的是陈述、推测还是其他已定义种类。通过检查，才保存为以后可查询的记忆。方案将这样的选择或整理结果称为 `Memory`。[^2]

原消息继续保留。Memory 的作用是让某些材料更容易在以后被找到，并将它与出处连起来。人物随后想核对甲当时的具体说法，可以沿来源回到原文；再次读取引用时，服务仍检查当前权限。[^3]

这一过程借鉴了 Yuralume 的认识提取与候选整理。现行方案在其基础上增加联系人范围、实际查看记录和来源语义的检查，因此写入结果要经过服务核验，不能只以提取模型的输出为准。[^4]

## 什么时候开始整理，谁负责保存

一次实际回复形成并保存后，就可以建立提取任务，不需要等待整段聊天结束。实际输出及送达状态是来源的一部分。人物已经查看、但尚未回复的来信也可以进入提取；她独自取得并实际接触的工具观察，同样有这个入口。[^2]

这些后台任务与直接交流使用相同的实际查看边界：来信必须已经形成 Exposure，正文才可成为提取输入。收件服务可以先做保存、签名校验和去重；人物侧的记忆、画像、情绪或生活整理则按实际提供记录取材。先让另一个模型分析未读正文、再传递结论，同样会越过这条边界。[^21]

围绕甲的消息，完整过程是：

```text
已查看的甲来信，或已经形成并保存的实际输出
    → 建立带来源 ID 的提取任务
    → 模型提出值得记住的候选
    → 服务核验范围、来源和语义种类
    → 持久保存 Memory
    → 建立索引任务
    → 后续按当前对象和问题查询
```

模型负责选择与整理有意义的内容，服务负责接受条件和保存，检索再负责把允许使用的材料提供给后续判断。来源校验失败的候选会被隔离，不能靠与已有文字相似而混入记录。[^5]

即时责任有另一条写入路径。[前一篇](05-改了安排以后还记得欠谁什么.md)中的改期和承诺，通过同一次人物运行中的领域工具提交。异步记忆整理可以保留相关经历，但不承担“过一阵才把刚刚说定的安排改掉”的职责。[^2]

## 习惯、临时状态和对人的认识怎样发展

甲的周会习惯和昨天的会议状态分别保留来源与适用时间。到了第二天，昨日状态不再作为“甲正在开会”提供；历史原话仍可查。如果只知道开会开始、不知道何时结束，人物拿到的是最后得知的情况及结束时间未知，而不是一个永久持续的会议。[^6]

对联系人的认识还分为候选和稳定摘要。候选先保留自己的依据，积累到需要整理时，再由阈值或空闲任务触发整理。整理会读取已有认识与新增候选；已有内容读取失败时，停止这次更新并保留重试，以免把“没能读出来”处理成“以前没有记录”。首版没有要求每天定时生成一场“梦”来补充内容。[^7]

认识候选先作为带来源的暂定理解保存。它不获得改写对方职业、人物过去或另一人状态的权威。这里的稳定摘要是对甲的认识，与经管理端确认的人物自身底稿有不同用途；新的交流仍可纠正以前的理解。同一条原话被多次提取，则仍然只有那一条来源，不能按提取次数累积成多份独立证据。[^8]

整理后的产物保留来源的联系人范围，各人的私聊不会汇成一份共享人生摘要。群聊材料也保留群聊范围，不复制成每个成员的一对一记忆。这样，整理前后的材料具有一致的使用边界。[^14][^21]

“人物目前相信某个说法”和“某事已被外部核实”同样分开。对于“今天很累”这样的日常自述，人物可以据此回应，不必先盘问验证。若要判断双方是否确实作过约定、是否取得使用许可，或某个发布动作是否完成，就读取对应原始记录。关系亲近与否不替这些记录签字。[^9]

## 先保存材料，再建立检索入口

原始消息、事件和材料先可靠保存；Memory 接受后，再建立索引任务。首版以 PostgreSQL 保存业务记录，关系键、时间和版本使用列，结构化内容可以使用 JSON；具体物理表如何划分仍待细化。全文和条件查询可以独立使用，向量检索按需要增加。[^10]

因此，向量服务暂时失败时，原文和事件仍在。索引任务标为待重试，查询可以按对象、时间和关键词降级进行，并如实说明当前检索能力；恢复后再补齐索引。持久记录和搜索入口各自承担一件事，建立索引不是事实得以保存的前提。[^10]

这也是对上游写入流程的一项明确适配：现行方案不沿用 Yuralume 那条依赖向量成功才写新记忆的路径。它保留来源可查性，但还需要实现索引任务、失败状态和重试的完整协议。[^10]

## 再次聊天时，怎样找到相关材料

当甲后来谈起会议，查询先确定这次允许读取甲的哪些材料，再按问题查找。拟议的 `facts.query / memory.search` 接受对象、时间或问题，返回相关材料及其来源；服务执行范围检查和检索。来源 ID 也经过相同权限检查。[^11]

首版的检索顺序优先考虑相关未解决事项，再看准确的对象、时间、资源或事项匹配，最后加入语义候选。实现上组合数据库结构化过滤、全文或关键词和可选向量。权重以后用回归集校准，现行方案没有给出一个已经验证的“重要度公式”。[^12]

对本例而言，甲的周会习惯、昨天那场会和眼下未处理的约定，可以分别找到。它们带着具体时间和来源进入人物判断，人物才有条件知道哪些仍适用于今天。最近的完整原话也有独立价值：它保留指代和语气，不能简单用一条较旧摘要替代。整轮输入怎样组合这些材料，将在[上下文篇](09-这一轮模型究竟拿到什么.md)继续展开。[^13]

去重也发生在这个链条中。相同来源 ID 的重复提取可以被幂等抑制；相似文字则只帮助合并候选。两条表面相近的话可能来自不同时间、不同人，或表达相互冲突的情况。服务不能用文字相似度消除来源冲突。Yuralume 的同类 bigram 过滤在这里仅是可借鉴的廉价提示。[^12]

## 新说法怎样纠正旧认识

现在再增加一个情况：甲后来说明，“不是每周都有，最近只是连续开了几次。”人物此前关于固定周会的认识就需要修正。

新记录保留这次解释的来源，并通过修正关系指向旧说法。原来那句消息仍可查询；根据旧说法生成的摘要被标记失效或待重算，后续查询使用新的适用状态，而不是让旧摘要继续独立证明“每周都开会”。摘要本身保留来源 ID、版本、适用时间和范围，所以系统能定位哪些派生内容受这次更正影响。[^14]

比较冲突时，检查是否涉及同一主体、同一事项，以及适用时间是否重叠。“上午开会”和“下午不在开会”可以同时成立。资料不足以判断时，查询返回未知或两种说法及其出处，再由人物按语境决定是否询问。[^5]

如果错误认识曾参与关系证据或跨场景影响，这次纠正还要传递给相应机制。下一两篇会分别说明感受怎样继续变化、信任怎样修复；记忆在这里先完成自己的闭环：旧来源保留、派生材料失效、重算后的内容重新进入检索。[^14]

撤回和删除也影响可读范围。后台整理与索引不能使已经失效的私密材料重新出现；完整的数据删除及晚到任务处理，在[管理篇](15-怎样暂停排障和清除人物数据.md)展开。[^15]

## 一句说错的话怎样留下正确的记录

记忆还需要处理人物自己的错误自述。假设她已经发出“刚买了咖啡”，但没有已提交的模拟生活事件，也没有实际结果支持这句话。

正常的出站流程应在发送前检查这类生活断言的来源。若漏检并已经发出，记忆仍可记录“她说过这句话”，同时留下待纠正标记；它不会据此产生一段已经买咖啡的共同生活。以后出现另一份合法证据，才关联更新相应记录。[^16]

这与甲的自述使用同一个基本区别：收到或说出某句话是一件可记录的事，句子所描述的经历还要看它的依据。记忆提取负责整理材料，不替一条没有根据的说法再认证一次。

## 工具观察怎样成为记忆

有些值得记住的内容不是从聊天产生的。例如，人物独自读取了一份资料，模型实际接触后形成了一个有价值的观察。它可以直接成为带来源的候选，无须先把这段观察对甲复述一遍。[^17]

工具执行本身另有可回查的记录：读取对象、时间、实际取得的内容范围及成功或失败。若后来读取视频，字幕、画面、评论分别取得多少，也应留在这些材料里。内部 HTTP 重试、向量批次和每个 token 属于执行记录，不逐条转成人物事件或长期记忆。[^17]

人物可选择保留某个观察或触动，而不是把全部工具返回长期装进聊天记忆。若她与甲共同讨论某段内容，甲的私人观点与两人的交往意义留在甲的范围；已获准共享的资料内容则可以独立成为人物自己的接触记录。给乙取材时，这两种材料仍按各自范围读取。[^17]

## 记忆能说明什么，还不能说明什么

这套记忆贯穿人物底稿、生活关切、逐人关系、当前理解、感受和行动进程，保存的是以后理解这些事情所需的依据。它区分事情发生了什么、人物当时知道多少、当时怎样解释、现在怎样判断，以及还有什么未办。框架尚未建模遗忘与记忆偏差，也不把这种组织方式当作人类记忆无损存储的说明。[^18]

对开发而言，接下来要细化的是完整的 Memory 与候选结构、提取任务和索引任务的状态协议、唯一约束、摘要版本与失效传播、稳定认识的整理阈值，以及具体检索配置。已经确定的先后关系仍然成立：材料先保存，候选经过核验，再用于允许范围内的检索；这些细节不能靠最终回复听起来顺畅来替代。[^19]

判断这条链是否接好，要看后续实际输入：次日不再把昨天的会议当当前状态，仍能查到甲的原话；更正后旧摘要不再冒充新判断；向量失败时来源仍可查且恢复后补齐；与乙交流时没有甲的原文、摘要、推断或私人来源。完整的试验方式见[实施与验证路线](C-实施与验证路线.md)。[^20]
