# 一份资源怎样进入她自己的创作

依据固定版本 `c5fddc8` 的待实施设计。本篇承接[真实浏览](12-一次真实浏览怎样开始和停下.md)，继续看兴趣怎样形成实际作品，以及别人提供的灵感怎样参与其中。

她看过一些图像风格内容后，想试做一组数字造型图。这件事可以完全由自己的兴趣发起：选择想尝试的方向，调用已允许的素材工具，看到实际结果，再决定修改、保留或放下。甲不必先提供东西，她也可以拥有自己的创作生活。

首版以“兼职模特的虚拟人物背景，喜欢穿搭、摄影和图像风格创作，另有普通内容兴趣”为内容起点。数字造型、授权素材的风格试验和真实观后想法，都能占用生活时间、产生可查看的成果。[^career]

## 先做出她自己能查看的东西

人物模型依据兴趣、当前活动和已有材料选择一次尝试。拟议工具 `asset.create` 接受具体创作动作及资源引用，由执行服务调用允许的能力，返回实际结果。耗时的生成或导出沿用前篇运行机制：先保存动作请求，等待期间让出人物决策机会，结果回来再结合最新处境继续。[^asset]

文件通过资产存储接口保存，并保留 hash。单机开发可以使用私有目录，部署时可以换对象存储；文件的后续公开仍经过授权作品流程。模型看到实际产物后，可以喜欢它，也可以觉得不合适、继续修改或不再使用。选择与生成结果分别保存，后来才能区分“她想试一下”和“确实做出了这份东西”。

如果一部分素材成功、一部分失败，工具返回各部分结果。人物根据已有产物决定缩小这次内容或推迟，作品依据仍是实际取得的素材。这里也允许正常结束而不公开：创作产生了一份作品，并没有同时产生发帖义务。[^result]

## 甲的灵感作为另一条入口

现在给同一场景增加一个情况：甲的来信已经被查看，其中附了一份图像风格 Skill。它可能是风格提示或模板，也可能依赖某些工具，甚至包含代码。

收件时先保存资源和甲的原话。人物根据审美与当前活动决定是否进一步了解。资源在这里是一份待理解、待检查的外来材料：它可以提供方法和灵感，但修改系统规则、取得账号权限是另外的授权问题。人物感兴趣后，程序把试用落实为受限创作任务。[^resource]

资源服务按内容分三类处理：

| 资源类型 | 怎样进入试作 |
| --- | --- |
| 纯提示或模板 | 检查来源、用途与权限，在允许的创作范围内使用 |
| 依赖已有受信工具 | 检查来源和权限，通过已有的限定接口完成试作 |
| 包含未知代码 | 先隔离审查，再在受限环境试跑；通过后才可进入生产工具目录 |

未知代码的试跑环境不持有私聊数据库、登录 cookie 或发布凭据，网络和文件权限按这次任务的需要给予。原始资源版本和授权保持可追查。审核通过的是特定内容或能力，后续调用仍走限定接口。[^resource]

这样，模型负责“这是否值得我试”，服务负责“这份材料能以什么权限执行”，工具负责返回真实成品。人物对成品的反应留给下一步判断。她可能采用，也可能试过后放弃；资源收到、尝试、产出和后续选择各自成为可回查的经过。

## 把作品与私人来由分别保存

甲的资源真的帮助她做出了一份作品。以后甲再提起，她应当能够理解这段来由；但乙看到这份作品时，并不因此获得甲的私聊。

为此，私聊事件和资源来源先保留在甲的范围内。实际生成后，如果要将这份作品用于公开，服务针对作品检查可公开性，再建立新的 `character` 范围作品记录。这个记录带允许共享的内容和实际生成结果。公开任务从这份材料取用，甲的私聊不会作为公开上下文一起带过去。[^split]

两类联系需要分别保存：

- **作品本身及其材料、素材版本**，用来查看实际产物、准备后续草稿，并回查它由什么生成。
- **谁提供了什么帮助**，由 `Contribution` 保存贡献归属，只供甲的关系回顾和有权限的管理流程使用。

同一个作品以后可以同时出现在公开记录和甲的私人回顾中。作品发布并读回后，公共事件指向它；甲的私密记录关联同一个公共作品 ID。于是甲后来谈到自己的影响时，人物可以取回这段来由；对乙则只取作品本身和乙有权获得的信息。[^split]

`character` 范围表示自己的可共享生活材料，是否公开还需要单独判断。未发布草稿就可能属于这个范围，但仍保持未公开。保存范围、公开使用许可和人物是否愿意发布，回答的是三个不同问题。[^scope]

## 许可怎样随材料一起传下去

服务通过 `PublicationGrant` 或已确认的自有材料规则判断特定作品可以怎样公开。对需要授权的资源，许可至少记录以下内容：[^grant]

| 许可需要说明什么 | 在这次创作中解决的问题 |
| --- | --- |
| 授权人和材料 | 谁授权使用哪份资源 |
| 用途和公开范围 | 允许拿来做什么、向哪些范围公开 |
| 署名约定 | 作品中是否需要以及怎样署名 |
| 期限和撤销状态 | 这份许可在后续使用时是否仍然有效 |

人物的公开选择另存。获得许可后，她仍可以决定不发；若决定发，草稿只带作品和允许公开的制作信息。素材许可要求署名时按约定处理，甲的身份和私聊来由则按各自许可处理。

检查也包括可识别性。截图、独特措辞、定位、EXIF 和若干细节的组合，都可能暴露私人来由。因此，公开作品的描述要在脱离甲私聊后仍能独立成立。去掉姓名只是其中一个处理动作，不等于已完成匿名检查。[^grant]

许可会随时间或撤销而变化。具体发布前怎样复核、撤销后如何处理远端作品，在[公开与反馈](14-作品怎样公开并收到后续反馈.md)继续展开。这里先完成可供该流程使用的作品、来源与许可材料；完整字段命名和数据库 schema 仍待细化。

## 很多人都提供资源时怎样选择

如果甲、乙和更多人都发来灵感，候选资源保存接收时间、对象和处理状态。人物当前只取得符合兴趣、权限与上下文预算的候选，再决定关注哪一份。资源筛选需要可以审查，私人创意仍留在自己的来源范围中。[^many]

先到或付费不自动获得优先顺序，未采用也不等于拒绝与那个人的关系。人物可以对实际成果感到高兴，也可以记得谁提供过帮助；这些反应来自发生过的经历，并继续遵守前文的关系机制。资源接收没有一个自动增加好感、公开感谢或制造暧昧的对应动作。

“送笔”的体验来自这条实际联系：她喜欢并自愿采用，作品留下了影响，提供者后来认出了它。系统允许这种结果，也允许资源不适合或最后不公开。亲近不需要独占暗示、争宠排名或故意制造误会来维持。[^relation]

## 虚构职业和真实产物怎样接在一起

普通虚构线下活动继续按生活篇的规则记录为人物世界中的经历。数字素材生成、平台发布，以及将来真人参与的合作，则分别依据实际工具结果、真实交付与约定记录。账号对外标明虚拟人物，数字造型图可以作为她的数字作品展示。[^truth]

这让兼职模特背景与实际可做的事情有了连接，同时保留来源的不同：一张生成图支持“这次做出了一张造型图”，真实摄影师返图、品牌委托或商业报酬则需要对应事实。未来确有真人摄影师或设计师参与时，再保存真实合作的交付和约定。

职业知识目前仍有具体缺口。公开资料不足以构成大陆兼职模特的完整经验手册，广告和骗局报道也不足以代表常态收入或工作流程。小红书的进一步资料依赖后续可用账号；其他创作机制可以先继续明确。

待补的职业资料卡应保留作者或来源、角色、地区、时间、原文片段与适用边界，按合作沟通、拍摄准备、素材交付、使用范围、费用纠纷等问题积累。具体城市、雇主、报价、客户和工作经历仍未确定，首期也不具备成熟从业者的全部知识。[^knowledge]

## 实现还需要补齐什么

这条机制已经区分了人物选择、资源检查、实际生成、作品记录、私人贡献和公开许可。资源服务、受限试跑环境、资产工具与许可检查的具体接口、完整 schema 仍需实现；职业资料与最终人物设定也要继续补足。

公开候选中的私密过滤借鉴 Yuralume；私人资源与公共作品分别保存、同一作品按联系人取材，以及这里的资源安全流程，是本项目为共享人物增加的适配。上游核心提示词如果实际采用，仍按固定版本和原字节保存，胶水材料独立维护。[^origin]

接下来只增加一个问题：她已经有一份可以公开、也愿意公开的作品，怎样真正发到平台上，并接住之后的反馈？
