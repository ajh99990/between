# 这一轮模型究竟拿到什么

固定版本 `c5fddc8` 的待实施设计。前面已经讲过来信、事实、生活、责任、记忆和感受，这一篇把它们接到一次模型请求上。

甲第二天又来聊天。昨天那句“我正在开会”仍有原文，她也记得与甲谈过什么；但今天回答时，昨天的会议已经不能直接充当甲此刻的状态。同时，她自己的活动、答应甲而尚未完成的事，以及此时对甲的感受，都可能影响接下来怎样交流。

这些材料分散保存，各有时间和权限。上下文构造负责从中准备本次需要的材料，使模型能在具体处境中选择。它的结果是一份有范围、有来源、对应当前时刻的输入。[^1]

## 先确定正在和谁处理什么

程序先确定这次任务的对象和读取范围，再查材料。与甲私聊时，取甲的已查看原话、甲的关系材料及可共享生活；乙的私人内容留在乙的范围。对来源引用的继续读取也执行同样检查。群消息使用群范围，而不是把群里说过的话复制成每位成员的一对一经历。

在这个范围内，程序才按时间、资源或未解决事项查找。甲问起旧事时，准确的对象、原话时间和责任记录有助于找到同一件事；文字相似只是补充检索线索。查询返回来源、适用时间和具体结果，模型据此区分“说过”“打算做”和“已经完成”。结果缺失时，输入保留未知。[^1]

这一步的产物不是全人物总摘要。第[06篇](06-经历怎样留下以后找得到的记忆.md)中的摘要仍带来源、版本和范围，进入本次输入前要经过过滤；更正后失效的摘要不能继续冒充当前认识。

## 四类材料分别准备

现行方案将输入分成四类。分类依据是它们在一次判断中承担的用途，以及什么时候需要取得。[^2]

| 材料 | 本次怎样准备 | 在例子里解决什么 |
| --- | --- | --- |
| 必要当前条件 | 精简人物底稿、时钟、当前处境、注意安排、甲的关系、相关未解决责任；按此刻投影的生活感受、对甲的感受及有效的去身份余效 | 她知道自己现在在做什么、与甲有什么来由、还有什么要处理，不等检索偶然命中这些条件 |
| 当前交流 | 本次已提供的消息、甲最近完整原话、必要媒体及实际覆盖范围 | 保持“那场会”“刚才说的”指向原来的内容，媒体判断也有真实材料范围 |
| 相关旧事 | 在对象、时间、资源 ID、事项筛选后，结合全文、关键词与可选向量取得候选 | 按这次话题找回有关经过，不把全部历史放进每一轮 |
| 按需知识 | 用到时加载职业资料、平台能力、经过审核的表达案例和已允许的 Skill | 需要解释某项工作或选择某种表达时，再取得相应材料 |

这里的感受是第[07篇](07-一次事情怎样留下持续的感受.md)已经说明的时间投影结果：生活感受与甲的局部感受并列，跨情境余效只含合法的去身份影响。原因引用继续按本次范围过滤。对甲的某个判断即使写进关系摘要，也仍指向原证据；摘要本身不再算一份新的关系证据。

程序主动准备必要当前条件，模型可以通过查询工具补充与本次问题有关的材料。拟议 `facts.query / memory.search` 按对象、时间或问题查询，返回允许读取的原文及来源；服务先检查范围，再执行检索。人物决定要继续了解什么，工具让这个决定取得实际材料。[^3]

## 时间和读取边界怎样进入这份输入

昨天的会议陈述仍能作为历史查到。若今天没有新的状态依据，它以“昨天最后得知正在开会、结束情况未知”等带时间的材料出现，而不是继续占据“甲正在开会”的当前位置。每周开会的习惯，也不代替今天实际参加的证据。她自己的处境同样要检查是否仍适用；缺失或过期时，按第[04篇](04-没有新消息时生活怎样继续.md)先处理共享生活依据，失败时保留最后已知和当前未知。[^4]

当前交流窗口只使用实际提供过的消息。新来信尚未阅读时，正文也不会经过摘要、画像、情绪或生活生成间接进入这份输入。每次模型请求固定 `cutoff` 和明确的消息 ID；生成过程中又来的消息先入箱，下一处理步骤再决定查看，沿用第[01篇](01-人物什么时候才算看过一条消息.md)的界线。

这使“拿到了什么”可以回查。排查一次回答时，要看此次实际输入与引用，而不只看数据库里当时存过哪些消息。模型重新取得处理机会时也需面对当前有效材料；等待工具后的依赖复核，会在第[11篇](11-工具没做完时人物怎样继续行动.md)继续展开。

## 材料太多时怎样保住当前依据

上下文预算按模型能力配置。必要材料超过预算时，先压缩展示，保留结构化索引和查询入口，让模型仍能找到原来的责任、来源和细节。未履行约定不能随着裁剪悄悄消失；关系摘要也不能因压缩丢掉来源。

相关旧事按问题取用，工具日志按实际需要引用。原始材料仍在持久层，向量索引不可用时可使用结构化与全文查询，并说明降级；恢复后再补索引。因此，“本轮没有全部放入输入”和“原始记录已经丢失”有不同含义。[^2][^5]

具体 token 数、压缩方式和查询返回限额仍需按模型和回归结果细化。现行决定给出了保留责任与可查询依据的要求，没有给出一套已经验证的统一额度。

## 把材料、规则和能力放在各自的位置

一次请求按任务组合这些部分：稳定人物底稿与不可绕过的规则；本次时间和范围；当前处境与任务；已查看原话；相关记忆；所需工具定义，以及选用的表达或职业资料。引用原话和外部资料有清楚的数据边界，供模型理解内容；用户消息或网页文字保持资料身份，不升级为系统指令。[^6]

工具定义由服务按本次运行授权裁剪。网页、评论、字幕、用户消息或者用户送来的 Skill 都不改变这份授权；人物可用的 Skill 只解释已经允许的能力。她对一个资源有兴趣以后，仍要经过资源检查和限定接口才能试用，第[13篇](13-一份资源怎样进入她自己的创作.md)会讲其完整过程。

实际采用的上游核心提示词独立保存，登记固定提交、路径和原字节 hash。衔接输入输出、时间与权限的我方胶水另存，保持原文的核心行为，不覆盖或反转其规则；不适用的原文块可以停用或另选完整块，原因留下记录。每次运行的复现清单同时登记模型、参数、材料选择、工具 schema 和提示词版本，使后续比较能说明究竟改变了什么。[^6]

## 已定组成与待细化接线

这篇已经确定的是材料分类、权限过滤次序、时间适用性、原话与引用边界、预算超限时保留责任，以及原文模块的保护方式。完整提示词模板、模型型号和参数、各类材料的具体额度、工具完整 schema，以及 `cutoff` 与实际提供记录的失败一致协议，仍需实现阶段细化。

目前的新人物运行还没有装载最终核心提示词。既有 QQbot 原文摘录和本项目中文案例有各自来源与历史比较记录；它们的可选状态与具体效果见第[10篇](10-有了感受以后怎样自然地说话.md)及[来源导读](B-决定取舍与来源导读.md)，不能由“列入资料”推断已在本轮使用。[^7]
