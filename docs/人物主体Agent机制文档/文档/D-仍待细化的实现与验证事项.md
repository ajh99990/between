# 仍待细化的实现与验证事项

固定版本 `c5fddc8` 已经形成设计选择。下面按实施需要汇总已有缺口；各机制篇仍在相关步骤说明局部边界。本表区分“已有约束，需完成实现”和“尚缺配置或效果证据”。

## 后续第一项：先研究并确定 Agent 承载基础

2026-10-27 用户新增的处理顺序：未来交回原作者处理这些问题时，先确定使用 LangChain / LangGraph、DeepSeek Harness（DSH），还是更适合项目的其他可复用基础，再据此细化后续实现与验证事项。用户认为承载基础未定会让后面的回答过于虚浮、难以落地。完整原意、候选和“不从零开发底层框架”等约束见[讨论反馈首项](../../discussions/对话过程中的小决策.md#agent-foundation-first)。

这项补充调整未来处理顺序，尚未选定框架，也没有启动研究或改变正式架构决定；下表仍是上述固定版本的缺口汇总，后续处理时需核对现行方案。

## 哪些效果还没有证据

设计选择不等于中文自然度或关系体验已经成立。仍要按[C-实施与验证路线](C-实施与验证路线.md)分别确认：

- 固定时钟、来源、权限、回放、结算、过去保护和外部动作防重是否在实现中成立。
- 相同人物、事件和可见材料下，EE适配相对文字状态是否带来持续性与选择方面的收益，参数是否合理。
- 主模型与表达资料在同条件下的表现，普通中文、自然收尾、适当亲近及边界是否得到实际目标使用者认可。
- 三平台真实读取/发布/管理和观察者可见范围；一条真实链与三平台首版完成分别判定。
- 资源确实影响作品并被甲认出、乙仍不获知私人来由时，“送笔式”体验是否受欢迎。不能预先承诺所有资源都会被采用。

概念框架还留下恢复时长、保留/遗忘或重新唤起、关切冲突取舍、中文中可信的局部变化等问题；遗忘和记忆偏差没有成为一套已实现模型。已有文献没有直接给出这些角色参数。[原02：现有缺口](https://github.com/ajh99990/between/blob/c5fddc8d3b3ae81b77d41cba4cede78286e8dd0d/docs/plans/人物主体Agent方案/02-决策依据与取舍.md#L79-L83)。

## 接入真实用户前的实例配置

部署成本、容量、数据保留期和最终人物设定需要确定；模型版本、参数、工具和提示词版本进入复现清单。人物自有账号、允许动作和资源预算由部署者明确，通常每帖不另找管理员审批，具体执行仍受服务权限与平台结果约束。

首版现行选择继续有效：允许有限普通虚构生活，也允许亲近和共同经历；排他恋人承诺不在首版提供范围。这些产品边界与实例参数、效果验证分别维护。
