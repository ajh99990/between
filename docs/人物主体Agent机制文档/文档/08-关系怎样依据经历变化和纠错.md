# 关系怎样依据经历变化和纠错

机制说明 · 依据 Between 固定版本 `c5fddc8d3b3ae81b77d41cba4cede78286e8dd0d` 的待实施设计。

上一篇里，人物因甲的一句催促有些不快，也可能在澄清后缓和。这一篇再给交流增加后续：甲知道她要先完成工作，答应晚些再聊，后来确实等到约定的时间才继续。

她当时是否烦躁、愿不愿继续聊，以及以后是否相信甲会尊重安排，可以分别变化。甲的一句道歉、一个承诺和一次实际履约，也各自提供不同材料。关系机制要保留这些区别，让以后对甲的理解有据可查。

首版以 **EE 的信任账本，加上有来源的关系理解、边界、共同经历与承诺** 延续关系。模型理解某次行为对双方意味着什么，服务保存和结算合格证据，后续人物运行在甲的范围读取这些材料。例子仍是自拟推演，结果尚待验证。[^1]

## 关系先记录具体的人和具体的事

两人渐渐熟悉后，需要记住的不只有“信任多少”，还包括人物已经了解甲什么、哪些相处方式舒服、哪件事仍未说开，以及答应过什么。这些认识引用实际交流或行为，关系事实与主观评价分别保存。[^2]

例如，甲说明最近会比较多，进入的是带来源的认识；两人讨论过一个话题，形成共同经历；人物提出忙时不想被连续催促，形成可回查的边界表达。它们让模型有条件理解下一次交流，却不因此自动成为信任账本中的同一种加减项。

关系变化通常先落在受影响的方面。接受一次解释，可以改变对那次迟到或催促的理解；愿意继续聊天，不必同时意味着愿意把重要事情交给对方。喜欢与可靠性、熟悉与可披露范围也各自成立。严重的单次事件可以迅速改变某一方面判断，现行方案没有要求一切关系变化都必须缓慢或重复很多次。[^3]

关系记录也包括人物自己的行为。如果她忘记了答应甲的事情，要分别保留她想补救、实际道歉、真正补做以及甲如何回应。她可以因此有所感受，但不强制每次都进入内疚，也不能替甲宣布已经释怀。[^4]

## 哪些经历可以成为信任证据

在本例中，甲承诺晚些再聊，先给人物一个未来预期；后来实际尊重安排，才增加一份可以评价的行为材料。模型需要说明，这件事改变的是谁对谁、在哪个方面的认识。当前不快本身不会自动扣信任，道歉也不必立即把长期信任加回。[^5]

模型可通过拟议的 `relation.record_evidence` 提交已看到的事件、主观理解及期望版本。服务检查这份材料属于谁、能否读取、是否已经登记，再形成待结算的 `RelationshipEvidence`。现行方案给出的最小字段是：[^6]

```text
RelationshipEvidence:
  event_id, evidence_type, eligible, source_ids, settlement_id?
```

除此之外，账本要求每条证据有唯一 ID，并能区分未消费与已消费。`eligible` 表示它是否符合结算条件；`source_ids` 保留成立依据；结算后记录关联的结算并标为已消费。字段清单是适配契约，完整物理表、状态表示和工具返回 schema 尚待细化。[^6]

上游证据类型和权重可以用于第一轮对照，但名称并不替宿主完成语义判断。例如，`explicit_trust` 不能解释成“甲说相信她，所以她必须更相信甲”。若无法说明证据究竟改变谁对谁的认识，这条证据就不结算。[^7]

赠送物品、付费、关注、点赞和消息数量都不直接换算成关系分。甲推荐的方法确实好用，可以成为偏好与共同经历；它是否说明甲可靠，需要另有相应理由。关系会发展，但不存在靠重复同一句夸奖或大量消息自动升级的通路。[^7]

## 一批证据怎样只结算一次

证据首先保存为可核验的材料。短评价批次关闭时，服务把合格且尚未消费的证据交给 EE 结算，保存输入证据和结果，并标记这些证据已消费。下一批次即使再遇到同一来源，也不能重新当作一份新证据。[^8]

人物可能在等下载时暂停，而 EE 要在会话关闭后结算证据。首版把这个会话对应到一个短评价批次：`session_id` 由 `run_id + evaluation_batch_id` 派生。当前批次的证据提交完、进入工具等待之前就关闭并结算，无须等待慢工具的最终结果。恢复或新消息开新批次，同一来源证据跨批次仍防重。批次无需等整段聊天结束，也不绑定可能等待很久的整个人物运行，因此等待中的运行不会长期占住关系的 active session。[^8]

在保存层，宿主读取数据库中的状态副本，调用 EE 接受和返回状态的核心函数；新状态、证据、锚点和结算键一起事务提交。稳定的来源、评价修订、证据与结算键承担长期幂等，版本冲突则重读。上游有保留窗口的防重集合不足以独自担任永久账本。[^8]

正常消费者也在这条链上：后续与甲有关的人物判断读取已经接受的关系状态、来源及未解决事项；与乙交流不读取甲的关系证据。一次调用失败时，模型必须获得实际结果，不能把自己提出的变化当作落库成功。本批情绪接受结果先交回模型供行动选择，选出的回复或动作由投递、执行服务报告实际结果；证据信任在有限批次关闭时结算，进入慢工具等待前的关闭仍按上面的时点进行。原方案并未规定本批所有信任都在第一次回复前完成。具体返回及后续注入协议还需细化。[^9]

首版不开启 EE 的缺席信任衰减。甲几天没联系，不会因此被自动扣信任；双方有没有疏远，要看实际交流和人物的理解。普通收尾与返回自己的生活也可以自然发生，不需要把持续在线当作维持关系的义务。[^10]

## 如果结算过的证据后来被推翻

再增加一个分支：人物曾把甲的某次行为理解成不守约，形成证据并完成结算；后来查到原始约定，发现自己把时间记错了。仅追加“误会解开了”还不足以修复账本，因为旧证据仍会留在计算结果里。

服务首先把错误证据标为 `invalidated` 或 `superseded`，保存它为什么失效、被什么新材料纠正。接着找到错误证据生效之前的可信检查点，从该基线及仍然有效的证据出发，按原顺序和记录的算法版本重建当前信任。修复保留旧结算及其被替代关系，不把撤销一次错误扣分登记成一次新的奖励。[^11]

为了让这件事有可用的起点，方案规定保存 `TrustCheckpoint` 和结算记录。检查点包含关系作用域、算法版本、状态版本、截止证据序号与基线值；每次结算保存输入证据和结果。修复时据此判断从哪里开始、采用哪一版算法，以及哪些历史结果被新结算替代。[^12]

```text
新来源澄清了旧事
    → 标记错误证据失效或被替代，并保留纠正来源
    → 查找错误生效前的可信检查点
    → 按原顺序和算法版本重放仍有效的证据
    → 保存重建结果与修正记录，替代旧结算
    → 后续读取修复后的信任；关联余效终止或重算
```

如果缺少可用基线，服务停止自动重建，保留待复核状态，不反推出一个看似合理的分数。修复期间提供最后确认的状态与待复核说明。重放只重建内部信任，不重发历史消息、不再次执行外部动作。[^11]

## 修复信任，与感受继续变化各自完成什么

错误证据被排除后，信任不再承受这份错误造成的持续影响。同时，人物在误会里曾经有过烦躁；这段感受怎样延续，仍按[上一篇](07-一次事情怎样留下持续的感受.md)的规则处理。

PAD 和 pulse 不做历史回滚。纠正与新理解成为新评价，从当前时间投影后的状态继续变化；旧评价不再作为仍成立的原因或再次结算。相关跨场景余效终止或重算，已留下的短波动可以衰减，也可被新评价改变，不要求立即归零。[^13]

这一区别也适用于没有误判的普通修复。甲确实做过一件令她不舒服的事，后来道歉、改变做法，可以使当下感受、继续交流的意愿及未来可靠性判断分别发展。接受道歉不等于所有方面同时重置，也不能由此推论道歉永远无用、关系永远不能修复。[^3][^14]

## 约定、亲近和共享人物的边界

普通承诺仍然允许，例如约定晚上聊某个话题。它们由[安排与责任机制](05-改了安排以后还记得欠谁什么.md)维护，本篇消费实际承诺和履行记录作为关系理解的材料。出现重复排期时，模型决定怎样调整，程序返回已占用时间并保护其他联系人的私密内容。[^15]

首版允许人物与很多人熟悉，产生不同的私下共同经历，也允许她喜欢并采用他人推荐的方法。一个人说“你是我女朋友”，不会因此自动建立双方承诺；首版也不建立或暗示面向每个用户的秘密排他恋人关系。未来若支持恋爱承诺，需要另行设计可公开解释的关系模型，不能靠亲密分数越线自动开启。[^2][^15]

这项边界来自本项目对共享人物和身份透明的选择，不是某个上游算法证明了它更受欢迎。它保留有根据的亲近，也保留与不同人不同的交往历史，实际体验仍待以后验证。[^15]

## 一个人的影响怎样留在作品里

关系经历可以延伸到共同关注的事。以后甲若推荐一种创作方法，人物因为喜欢而实际采用，后来真的完成公开作品，甲可以认出自己留下的影响。这种“送笔”体验依赖她自己的选择、真实采用和真实产物，不由礼物触发固定感谢、自动发帖或关系加分。[^16]

公开作品不必自动公开提供者。私密素材、聊天内容及可识别信息需要明确使用授权；作品的共同来历保存在相关对象范围，其他人不会因此获得那段私聊。系统也不假造礼物或感谢，不用作品刻意暗示三角关系。资源许可、实际制作及发布核查分别在[创作篇](13-一份资源怎样进入她自己的创作.md)与[公开篇](14-作品怎样公开并收到后续反馈.md)继续展开。[^16]

## 这套账本能验证到哪一步

本版保留 EE 的信任维度，其他关系内容用带来源的理解和记录表达，不再叠加 Eros、BetterSimTracker 的多套数值，也不补造欲望、依赖或嫉妒评分。采用边界服务于前面这条可查的经历链，不能用更多分数代替证据含义。[^2]

完整实现还需要细化关系理解、边界、证据和检查点的持久结构，证据与结算唯一约束、纠错状态及工具结果协议。已定的条件是：来源可查、归属明确、合格证据一次消费、错误证据按可信基线修复，以及修复过程中不重放外部动作。[^6][^11][^12]

验证时要分别查看证据链和行为：一次道歉是否被无条件加分，同一证据重试是否再生效，久未联系是否被扣信任，错误证据是否真正从新结算中排除，甲的证据是否进入乙的实际输入。关系数值漂亮、持续聊得久，或两个模型彼此认可，都不能代替这些检查。[^17]

框架中的关系、信任与修复研究帮助区分这些问题，不能直接提供本人物的参数。原研究存在样本和任务限制，也没有证明大陆年轻女性在普通中文聊天中的变化模型；理论来源与局限见[决定取舍与来源导读](B-决定取舍与来源导读.md)。模型对照及人工阅读的完整安排见[实施与验证路线](C-实施与验证路线.md)。[^14][^17]
