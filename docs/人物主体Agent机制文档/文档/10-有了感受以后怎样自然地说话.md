# 有了感受以后怎样自然地说话

固定版本 `c5fddc8` 的待实施设计。前面已讲清人物取得什么材料、形成什么判断和感受；这一篇继续到对外表达。

甲说“今天有点累”，她可能只是接住这句普通分享。过一会儿，甲发来图片，请她帮看一个字；另一次，甲在已经得到回答后，仍连续要求逐项描述同一张图，却没有说明新的需求。它们都进入同一个人物的交流，但她此刻准备做的事情不同：陪着说两句、认真帮忙、确认需求，或者表达不愿继续。

现行方案由人物模型先形成简短回应意图，再按语境选择表达材料，最后组织措辞。感受参与这次选择，表达资料帮助把握分寸。资料只指导表达，不改写原事实，也不强制替她选择沉默。[^1]

## 先明确这次想怎样与对方相处

一次回应要结合四件事：发生的事情对她意味着什么、她此刻有什么感受、她在与谁交往、这一轮准备做什么。这些沿用前面已有的事件、关系和当前状态，在同一人物运行中理解。

如果甲是熟悉的人、图片可读、她也有余力，识图可以是正常帮忙。若同一要求已经答过、仍反复出现，对方又没有说明新需求，她可以问清具体想知道什么，也可以表示不愿继续。面对直接身份询问，她如实说明虚拟身份，语气仍然可以自然。普通分享可以轻接后收尾；明确求安慰或建议时，也可以投入更多。[^2]

因此，回应意图描述这次交往动作，而不只是一个情绪名称。同样有点疲惫，可能仍愿意帮甲看一个字；同样不耐烦，也可能先澄清。熟悉、无压力且有拒绝余地时，可以有轻微试探亲近；这取决于当下关系和语境。

## 表达资料怎样帮助这次回应

当模型需要表达材料时，按交流意图、关系范围、相关情绪和具体失败共同定位。方案给出的资料单元保留六部分：[^3]

| 资料内容 | 使用时回答的问题 |
| --- | --- |
| 适用情境 | 这是什么关系、来话和处境？ |
| 不合适回应 | 过去容易出现怎样的偏差？ |
| 不合适的原因 | 问题是持续管人、误解意图、过度文学化，还是其他语境失配？ |
| 可接受方向 | 在这个情境中可以怎样回应？ |
| 原说法仍可能合适的条件 | 哪些情况下较长安慰或具体建议其实有需要？ |
| 来源与实际结果 | 这是原创候选、上游原文，还是已有比较记录？表现如何？ |

例如，甲只是报告“今天终于弄完了”，资料可以提醒模型留意这可能已是话题收尾，不必自动加上作息提醒、总结和追问。若甲明确需要安慰，前一个例子中的短回应又未必足够。资料保存适用例外，才有助于模型判断具体需要。

正例提供一种可能方向，反例解释行为与语境问题。它们不是固定台词或词汇黑名单。乐观主要体现在怎样理解事情、作出选择；脆弱可以存在，拒绝也可以直接，而不必分别变成索取安慰或侮辱。新发现的失败要保存完整前后文、错点与复测结果，再用于修改资料；未经确认的模型答案仍是候选。[^3]

## 哪些材料已经有，怎样装入请求

当前有两类可供继续比较的材料。

一类是本项目原创的普通中文反面案例及具体回应示例。前者已有获准编写和对照记录；具体回应示例 v0.2 没有显示明确整体优势。它们可作为独立模块继续比较，历史记录只说明相应实验范围。

另一类是 QQbot 的既有原文摘录，其中七行措辞材料作为可选模块。摘录保持固定提交和原字节 hash，适用说明单独保存；整份游戏直播人格并不因此一并装入。对照词也不做全局替换，避免把“现在”改成“未来”，或把“不知道”变成已经拥有查询能力。[^4]

使用时，选中的表达资料随第[09篇](09-这一轮模型究竟拿到什么.md)的合法上下文进入同一次人物运行。各原文模块独立保留，记录选取块、注入顺序和 hash；需要的时间、权限和行为衔接另存胶水，胶水不覆盖或反转上游核心规则。若模块冲突，停用或选择另一完整块，不在原文中改词后继续称为原样复用。

这次文档固定版本尚未为新人物运行新增或装载最终核心提示词。逐块选用与实际模板，仍属于后续实施和比较的工作。[^5]

## 回复发出以前，核对哪些具体问题

模型组织好回应后，出站服务做窄范围核对：正文是否越权披露私聊或系统秘密，动作完成声明是否有实际结果，身份是否真实，以及是否违反已保存的明确承诺与产品边界。[^6]

自己的当前或近期生活断言也要能找到依据。例如，“刚买了咖啡”要能指向已成立的处境、事件或结果；若没有，修正的是这句断言。合法的新生活选择要先经过第[04篇](04-没有新消息时生活怎样继续.md)的生活服务独立提交，再成为回复依据；服务不从待发送的错误草稿自动补模拟事件为它背书。主观感受、比喻和普通语气则按各自含义理解，不机械要求每一句都有外部回执。

这里沿用第[03篇](03-一句话怎样成为可回查的记录.md)的事实来源和范围。文字里出现“AI”“模型”“工具”并不是自动拒绝条件，直接问身份时尤其需要如实回答。正常用户看到的是对外消息；内部提示、完整模型输入、工具诊断和凭据不混进聊天或语音输入。

窄检查若发现冲突，返回具体位置及来源，由同一人物上下文修正。修正次数受运行预算限制；仍未通过时保留错误、不投递，留待恢复。系统记录这是输出处理失败，不把它写成人物有意沉默。具体重试次数尚未给出。[^6]

## 怎样保留个性，又能逐步改善表达

“语言自然吗”和“这句话越权或虚报完成了吗”是不同问题。后者由上述具体检查处理；前者主要靠离线对照、正常速度交流和人读完整记录来改善。首版没有一个可以任意重写全部措辞的在线“真人感”评分器。

比较时先固定人物、模型、事件和可见历史，再逐项改变表达模块。保留表现差的前后文与适用例外，观察回应意图、普通措辞、跨轮连续性和边界；不只看一句话是否漂亮。甲乙各自看到的材料仍独立，不能靠混入别人的私事让某组显得更了解人。

这套表达机制允许普通、不完美的选择。她可以结束话题，也可以在有需要时认真回应；同一人可以一边疲惫一边愿意帮忙。它不把“可爱”“乐观”或“18–28岁女性”转换为统一话术。具体中文效果和用户是否喜欢，仍要通过[实施与验证路线](C-实施与验证路线.md)中的真实模型及人读比较确认。[^7]

## 这部分仍需细化的内容

资料单元的组成、按语境选材、原文与原创模块分开、窄检查职责和失败分支已经确定。资料的完整存储结构、具体检索接口、实际选用原文块、最终提示词及胶水版本、主模型参数和修正预算仍需落实。新增测试样本也需要来源和评价，不能自动从模型输出积累成未经审查的“正确答案库”。
