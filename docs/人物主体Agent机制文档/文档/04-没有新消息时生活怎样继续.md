# 没有新消息时，生活怎样继续

临时重组稿 · 2026-10-25 · 依据 Between 固定版本 `c5fddc8d3b3ae81b77d41cba4cede78286e8dd0d` 的待实施设计。

前面几篇里，甲的来信经历了保存、选择查看和留下实际提供记录。现在给这个人物增加一件自己的事：在已经设定的虚构居所里，她准备做一顿饭。

甲有没有继续发消息，不决定这顿饭是否还存在。她可能继续准备食材，中途休息，觉得时间不够而改做简单一点；稍后乙问起近况，也应面对这个人物同一份生活。系统需要保存她已经选择的活动、目前已知的进展，以及什么时候再回来判断下一步。

这里的持续性来自**已经保存的生活依据，以及后续重新处理它的机会**。模型在有事情需要理解和选择时运行；生活服务保存选择及进展；定时器在检查点到达时带她回来。它们共同维持生活，模型本身不必一直在线。[^life-main]

## 一件自己的事，为什么不能由每段聊天分别续写

假设她已经开始准备午饭。甲来问时，系统提供这份近况；乙稍后询问时，也从同一个地方取得它。如果活动尚未改变，就沿用；如果她已经暂停做饭，则两边随后读到的都是更新后的处境。

这份共享近况叫作 `CurrentSituation`。它回答：系统此刻采用的活动是什么，已知进行到哪里，地点或环境知道到什么程度，这份信息什么时候确认、什么时候需要复核。生活领域服务负责提交它，每次人物决策和私聊输入都会读取这份当前依据。重要近况直接进入所需输入，不等待向量检索碰巧命中。[^life-situation]

这里共享的是人物自己的生活。甲为什么来找她、两人私下谈了什么，仍属于甲这一范围；乙可以知道适合分享的近况，却不会因为人物正在做同一顿饭，就取得甲的私聊内容。

当前活动可以是休息、虚构通勤、真实浏览或等待导出，不必事先对应一条日程。它也容得下并行的事情：她可以一边等水烧开一边聊天，文件导出也可能在后台继续。共享处境保存主要活动、适用时间和已知并行事项；具体外部动作执行到了哪一步，由后文的动作记录承担。[^life-situation]

## 继续生活时，她带着哪些已有情况

“做饭”并不是人物的全部状态。她可能想吃得简单一点，又想早点处理完一份材料，同时愿意和甲说几句。理解这次选择，需要保留这些并存的信息，而不把整个人切换成互斥的“做饭模式”或“聊天模式”。

人物的**底稿**提供相对稳定的依据：已有的虚构经历、价值取向、兴趣、常用表达和应对习惯，以及少量带条件的倾向。居所和做饭习惯应来自这里。倾向可以随经历发展，但一条来信不会整包改写这些依据；过去发生过什么，与她现在怎样理解过去，也分别保留。[^life-six]

她**自己的生活与关切**则更接近眼下：正在做什么，近期惦记什么，想完成或避免什么，为什么在意，还有时间安排、疲劳和注意状况。它们会随进展或重新考虑而改变。想聊天、做完饭、早点休息可以同时存在，不必先算出唯一目标才能行动。

面对甲时，还要带着**这段具体关系**：了解甲哪些事情，靠近是否自在，在哪些事情上信任他，双方各自承诺过什么，哪些问题还没处理，哪些话已经说过、哪些不愿透露。喜欢一个人不等于信任他处理所有事，熟悉也不授予全部秘密。人物自己的失误同样会影响这段关系；后面的责任和关系机制会继续解释怎样记录这些后果。

她**对当前事情的理解**保存已知、未知、解释和预期，并带着信息来源与确定程度。甲说“今天有点累”，她得到的是甲的自述；她可以据此关心，也可以尚不清楚原因。第三篇已经说明了说法与事实怎样分别记录，这里将它用于人物眼下的判断。

她的**当下感受与行动倾向**可以混合存在：有点困，同时愿意聊天；对一件事不耐烦，又想先确认情况。整体没精神也可能暂时没有明确原因。有依据的睡眠、饥饿和时间变化可以影响状态；系统保留未知原因，而不为每次波动补一场争吵。感受、想做什么和最后实际做什么分别变化。

最后是**当前行动与事情进程**：她正在继续哪件事，这次准备做什么，实际做了什么，是留待处理、暂缓还是结束。她可以接话、分享、询问、说明、道歉、补救、拒绝、暂停，也可以回去做饭或接受谈话收尾。结果不理想时，可以调整做法，也可以放弃。[^life-six]

这六类信息共同描述一个人，不要求六个 Agent、六份提示词或六张表。记忆贯穿其中，为以后保留依据：发生了什么、当时知道多少、当时怎样解释、现在怎样判断、还有什么未处理。记忆机制也不是一个掌握一切的内心旁白；主观相信仍与客观证实分别保存，不要求一律计算可信度分数。概念框架尚未建模遗忘与记忆偏差。[^life-six]

## 环境怎样参与这件事

人物自身之外，还有当下环境。居住城市是背景，但此刻是否有人在旁、是否方便听语音、网络是否可用，会直接改变行动条件。

| 环境方面 | 需要保留的情况 | 它可能影响什么 |
| --- | --- | --- |
| 时间与物理条件 | 当地时间、位置、声音、光线、温度、拥挤程度 | 能否听清、看清、移动或继续停留 |
| 在场者与社会场合 | 独处、同事在旁、家庭聚餐、正式会议，以及场合规则 | 哪些内容方便说，是否降低音量或暂缓某个话题 |
| 外部事情 | 到站、有人叫她、会议开始、停电 | 是否分配注意、中断当前活动或处理新事 |
| 交流条件 | 信号、设备、能否外放语音、有无隐私空间 | 信息能否送达，可用什么方式交流，动作能否完成 |

这些条件独立描述，人物怎样理解它们仍属于前面第四类信息。例如，“列车快到站”是外部情况，“准备下车”是她的打算，“觉得今天迟到了”是她的理解，“有些累”是自身状态。同一时刻可以关联这些信息，但更新其中一项不应自动改写其他项。[^life-environment]

环境存在，也不代表人物已经注意到。以检票口变化为例：场景中可以已经确定检票口换了，她却还没看见通知。后来实际看到通知，才获得这个信息；她也可能一时没看懂，之后才修正理解。**环境情况、实际察觉和主观解释，沿着各自的记录继续变化。**[^life-awareness]

环境有两种影响路径。一种经过人物理解：她注意到同事在旁，决定暂不谈私密话题。另一种直接限制实际结果：网络已经中断，她还不知道，尝试发送的消息仍可能发不出去。人物是否察觉，影响她的判断；环境的真实条件则同时影响行动能否成功。

她也可以主动改变条件，例如走到安静处、离开聚会、关掉通知，或者请别人稍等。此时分别看她想改变什么、实际尝试了什么、结果改变了什么。走到另一个地方后发现仍很吵，移动已经发生，想获得的安静条件却还没实现。只有实际获知的结果进入下一次理解。[^life-awareness]

自己、对方和共享情境也有不同边界。她可能不了解自己周围的全部情况；甲报告“我在吃饭”，只提供了这条说法，没有同时提供地点和旁人。双方通话或共处时，只共享有依据的部分，同处一室也可能注意到不同的事。环境更新只改变已有新依据的部分，换一轮消息不会无故换地点；过去的位置也不会永远被当作当前位置。[^life-awareness]

本方案没有据此选定全知世界模拟器、实时传感系统或完整环境生成器。未知的地点、天气、旁人继续保持未知；明确设定的模拟事件则保留时间与来源。环境可以因时间、他人行动和外部事情变化，但这不要求为每个无人聊天的空白时段补造事件。

环境如何影响选择，可以用三个独立场景比较。先保持人物、疲劳、交流意愿、关系和来话一致，并另外给定“这是私密话题”和“人物已经察觉当前环境”两个前提。独处时，她可以聊，也可以想休息；列车快到站时，她可以先确认车站，之后继续交流；同事在旁时，她可以换成文字、换话题或换个地方。场合提供行动条件，不规定唯一反应。“在办公室”还不足以推出她不能聊天，需要继续看实际活动、旁人和交流方式。这些是独立的概念对照，不是一段无交代跳换地点的同日经历。[^life-environment-cases]

### 一次变化怎样留下后续影响

她注意到的新情况，先与已有关切、关系和身体状态一起形成理解：这件事与自己有什么关系，影响了哪件事，原因知道多少，眼下能做什么。这个理解可能改变感受或行动倾向，也可能几乎没有影响。没有回信只是一个可观察现象，原因仍须从已有依据判断；忙碌或疲劳也可能源于她自己的生活，而不需要每次都有一条新来信。

随后，已有习惯、可用条件和当下打算一起影响行动。实际结果又可能改变环境；人物只把自己获知的那部分结果带入下一次理解。变化先落在有关事项上，是否进一步改变某段关系，要看此前经历、分量和后续结果。她做完饭可以轻松一些，同时仍困；换个话题不会清空尚未处理的问题，甲的责任也不会转成乙的责任。整体心境可以延续到另一场交流，具体情绪分区及外溢规则由后面的情绪机制展开。

这个反馈过程说明各类信息怎样相互影响，并不要求每句话串行运行全部步骤。普通接话、习惯性回应、平静或自然收尾，都可以保持大部分状态不变。感受不会强制推出一种动作；系统也不要求人物永远成熟、克制或温柔。兴趣和做法能够随经历发展，已发生的历史继续保留，对历史的解释则可以修正。环境使她暂停某个话题，也不自动表示心情或关系变冷。[^life-feedback]

## 从一次选择，到可供下一次读取的生活

回到做饭。人物先有经设定的起始处境，随后从当前时间向前推进。这个过程包含三次不同性质的处理。[^life-forward]

**开始时，保存已经作出的选择。** 生活模型读取当前时间、已有生活、兴趣或习惯、自己的关切和后续安排，选择开始准备午饭。服务保存带模拟来源的开始记录，更新共享处境，并留下下一次检查点。开始成立以后，近况可以说正在准备；尚未形成的成果继续留在后面。

**检查点到达时，再判断实际采用的进展。** 输入包括这段活动的起点、有效中断、实际工具动作和仍待处理的事项。对于允许的普通虚构活动，模型可以提出已经做了一部分、想换做法、暂时没有进展或准备结束。服务核对它与已确立情况是否冲突，再提交新的生活记录和处境。

**之后来询问的人，读取同一份已提交近况。** 甲和乙各自的私聊保留在各自范围，但人物自己的活动不会分成两条互斥经历。若接下来要发送一张食物照片，文字里的做饭进展并不生成图片文件；真实文件制作及发送仍要取得对应工具结果。

这几次处理不需要补齐每分钟动作。源方案选择粗粒度的开始、进展和结束，保留模拟来源、记录时间及所依据的起点。它可以续接已经开始的活动，不倒改已经对外确立的经过，也不从现在补写一段尚未开始过的上午生活。[^life-forward]

### 服务保存什么，模型负责什么

一份当前处境方便后续直接使用；同时还要留下变化经过，才能回查它怎么形成。第三篇介绍的 `Event` 在这里记录生活的开始、选择或模拟进展。事件可以发生在日程之外；日程会在下一篇作为未来安排展开。

| 记录 | 在生活推进中保留什么 | 后续消费者 |
| --- | --- | --- |
| 当前处境 `CurrentSituation` | 当前活动、来源、确认时间、复核时间、最近已知状态是否过期；以及地点或环境的已知范围 | 所有涉及人物当前生活的决策与私聊输入 |
| 事件 `Event` | 发生时间、记录时间、来源类型、读取范围，以及必要的对象或结果引用 | 状态重建、按时间取材、后续有来源的记忆候选 |
| 后续机会 `WakeJob` | 唤醒原因、关联事项、到期时间、是否仍有效、处理状态 | 第二篇介绍的到期处理入口 |

这些是业务记录的最低内容，不规定一对象一张表。事件由相应的入口、生活服务或执行服务写入，当前处境由生活服务提交，唤醒由服务与调度器保存、维护。时间继续遵守第三篇的约定：实际发生、写入、获知和计划时间分别保存；未知的精确时刻保留区间或精度，而不是补造秒数。[^life-records]

拟议的 `life.current` 用来读共享处境，`life.advance` 用来提出允许范围内的生活进展、来源和下次复核。LLM 在数据库事务外形成提议；服务在提交时检查来源、范围、时间和当前版本。一次有效生活变更，将事件、处境新版本和必要唤醒放在同一事务里保存。[^life-commit]

如果活跃生活已经改变，却既没有下一次复核点，也没有关联的到期任务，服务返回具体缺项，让模型补齐。程序不会替她选择一个新活动。版本已经变化时，也须读取新状态再判断，而不是覆盖它。管理员明确暂停人物则是另一种运行状态，由后面的管理机制处理。

这使后续表达有了可查依据：新生活细节先经过生活提交，再进入回复材料。若人物临时说了没有依据的“刚买了咖啡”，保存这句话只能说明她说过，不能反过来让它成为已经发生的生活。对外表达前的来源检查，以及错误说法的后续纠正，会在表达和记忆机制中继续展开。[^life-claims]

## 普通虚构生活可以推进到哪里

生活服务的提交权限来自既有底稿及首版限定范围。它允许虚拟人物具有普通日常，同时区分模拟进展与真实世界动作。[^life-bounds]

| 可以提出的普通进展 | 需要其他依据或维护流程的事情 |
| --- | --- |
| 既有虚构居所中的休息、整理、做饭、普通兴趣练习 | 现实用户说过或做过什么、现实双方的共同经历 |
| 已设定职业中的普通准备、小段工作进展、轻微拖延 | 新的重大生平、家庭关系、身份、重大疾病、事故或财产变更 |
| 与既有虚构背景一致的小感受和后续打算 | 真实搜索、观看内容、关注、发布、收款、文件生成结果 |
| 开始、暂停、结束低风险活动 | 现实摄影师已联系、真实品牌已邀约、已经收到真实返图 |

重大生活变化可以成为候选，进入人物设定维护；普通聊天不直接确立它。首版也没有采用长篇剧情导演、随机重大遭遇或完整世界导演。当前选择是让普通生活稳定延续。

这种生成仍需检查冲突，普通虚构生活读起来是否自然尚待验证。人物可以过平淡的一天，也可以没有明显新进展；增加日程条目或新事件的数量，本身并不证明人物更像一个人。

## 没有新来信时，下一次判断怎样到来

第二篇说明了“稍后再看”的持久唤醒。同样的处理机会也用于活动检查点：当下一次做饭检查到时，程序带入当前时间、已知进展、发生的变化和后续安排，让模型选择继续、结束、换一件事或休息。

检查点的意义是重新判断，不是到点宣布做完。模型也可以形成一次生活复盘，整理当前关切、未完成事项和近期自己的变化；复盘不要求生成新目标、发动态或主动找人。生活推进、公开内容、主动私聊分别有自己的后续条件。[^life-wake]

数据库可以定时查到期任务，但只有真实到期、可见通知、有效工具结果或恢复事项才调用模型。扫描频率是工程参数，不是人物思考频率。一次判断结束时，保存需要的下一次复核或唤醒；当前处理可以完成，也可以留下可恢复的失败。

随着后续章节加入已读待办和慢工具，这个入口还能接到承诺到期与工具回报。到时只取对应对象的允许材料，结合最新处境再决定。共享生活检查可以合并，但只能合并不含联系人私密材料的部分；各人的私聊和责任不会因此混成一份总日记。[^life-wake]

## 日程有空档，或近况已经过期时

未来安排帮助人物分配时间，却不必事先精确填满24小时。对当前生活，服务检查的是这份处境现在是否仍适用。[^life-current]

| 当前情况 | 接下来怎样处理 |
| --- | --- |
| 有仍有效的处境 | 直接沿用，不为每条消息重新规划生活。 |
| 到了检查点 | 先查实际结果、已知中断及后续约定，再让模型选择下一步。 |
| 没有当前活动，也没有计划 | 先用共享生活材料作一次生活决策；从习惯、兴趣、关切及当前时间选择，提交后再用于私聊。 |
| 处境缺失，模型或存储又不可用 | 保留最后已知与“当前未知”；仍可处理不依赖当前活动的交流，暂不声称正在休息、空闲或已经完成。 |

初次启动需要经设定的起始处境。准备首个人物时，要有普通而具体的生活底稿、必要经历和带条件的惯常做法；眼下事项应有原因、进展与限制，具体关系和当前理解分别保存。环境列出已知的时间、地点、在场者、外部事情、交流条件及确认程度，人物实际获知的内容另记在理解中。这样，一句“她住在某城”才不会被当作当前场景已经准备完整。首个人物的具体底稿仍待后续细化。[^life-start]

之后的空档处理不是回头补造人生，而是从现在恢复可用的生活依据。每次对外回复之前，应有仍适用的共享处境，或者明确保留未知；不能让甲乙的私聊分别填补这块空白。

## 睡觉、检查稍晚和服务中断，分别怎样继续

她选择睡觉时，这项活动和注意安排仍有效，系统留下一次起床检查，普通来信继续入箱。如果已有定时承诺，要在入睡选择时处理它；睡觉本身不会删除责任。睡眠期间无需反复调用模型询问是否醒来。[^life-recovery]

若服务正常，只是检查点执行稍晚，程序使用当前时间和最新状态，从已存起点判断进展。多个过时的生活检查可以合并成一次当前判断，实际执行时间如实保存；不同承诺仍各自保留。

服务中断时，原始输入、未完成意图、承诺和唤醒都需要持久保存。恢复后先核对仍在执行或已经完成的真实任务，再进行恢复判断。跨过活动期限不意味着补演一串错过的浏览、发布和生活事件：系统保留最后已知与中断，从现在继续，没有回执的动作仍保持未知或待核对。

对外交流可以继续使用充分有据的部分；依赖缺失经历的问题保留不确定，等待处境恢复。人物不必每次都讲技术故障，也不能靠临时编造“刚开完会”解释缺失。已有感受可以按选定机制随时间演化，这只是在延续已有状态，不是补造中断期间的新刺激。具体任务领取、慢工具交接、版本复核和未知结果对账将在第十一篇深入。[^life-recovery]

## 怎样检查这条生活线是否真的连起来

可以先按下面几组条件检查记录与输入，再在获得授权后检验真实模型行为：[^life-check]

- 甲乙同时问近况时，两次输入引用同一共享版本及相容的生活来源；各人的私聊材料保持分开。
- 一天没有新来信，休息、兴趣和关切仍有正常推进；每次检查也允许平淡、不发帖、不主动联系。
- 检查点到达后，既能看到新进展，也能看到无进展或失败；真实浏览失败不会变成“已经看过”。
- 只改变环境而保持人物、关系、心境与来话相同，行为差异来自实际条件；没有看到检票口变化时不提前知道，网络限制也不因未察觉而消失。
- 想去安静处、走过去、发现仍吵分别有依据；下一轮不会无故换地点，也不会把尝试当作目标已经实现。

若对话频繁即兴补近况，优先查当前处境有没有实际进入输入、是否过期、生活写入是否先于回复。若生活毫无变化，则查检查点是否只有扫描，实际从未进入生活决策。概念结构、真实行为与中文措辞需要分别检验，单一“像真人”评分不能替代这些检查。

有意义的变化可以留下简短检查材料：依据是什么，原先的判断或状态是什么，后来改变了什么，哪些仍未变或未知。例如，一种解释改变了她对责任的理解，但饥饿和时间紧仍然存在。这类材料用于检查连续性，不要求记录隐藏思维链或向用户报告心理；没有有意义变化时，也可以不新增一条。概念框架没有给出统一恢复速率，后续仍可采用带明确范围与时间语义的数值实现。[^life-observe]

## 实现时还要细化什么

共享处境、前向普通虚构生活和事件触发已经选定。仍需细化的是这些机制的具体实现与实例配置：完整表结构及工具schema、复核时间的选择参数、环境信息的取得方式、起始人物底稿，以及生活生成的冲突检查怎样稳定执行。源文的半小时等例子不规定统一检查周期。[^life-open]

六类概念也没有给出完整人类心理模型：恢复时长、遗忘与重新唤起、多种关切冲突时的取舍、普通中文表达是否可信，仍需要相应材料和验证。当前目标是一个具体虚构人物；候选年龄、性别或兼职背景都不能代替一个人的底稿，也不能推导整个群体的行为模板。

这条生活线现在有了起点、持续使用的近况、可追查的变化和下一次机会。下一篇增加一个更具体的问题：甲提出的请求改变了她原本的安排，哪些计划可以改，哪些已经对外承担的责任还要继续记着。
