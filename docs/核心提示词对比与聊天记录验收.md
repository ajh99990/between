# 核心提示词对比与聊天记录验收

## 范围与结果

2026-10-19，在用户明确授权后完成三组各 15 轮、总计 45 次真实模型回复。使用同一 `gpt-6.1-sol`、`medium` 档位和相同预设用户消息，三组历史独立。每轮通过正式聊天接口生成、确认完成并落盘；完整聊天与请求证据保存于仓库外的专用私有实验目录，不提交源码仓库。测试没有读取日常会话或改动日常数据目录。

实验代码和可复查运行命令见 [对比工具](../experiments/conversation-comparison/README.md)。后台现在支持“会话与任务 → 查看记录”，可以阅读完整可见文本、搜索定位及查看受支持图片。它不显示模型提示、世界书、隐藏消息、推理、操作内部状态或凭据；不是实时旁观尚未保存的生成流。

## 原文边界

- 基线保留提交 `ec78946a003f99ba01f839a3eaa77fbe2273f383` 中的内置米拉与原角色引擎组装行为，不代表管理员当前自定义角色配置。
- MaiBot 固定 `f01f2c22df5e0ba3cb1c5bc3b6ced5d5ec39c1cb`，用原始方法体和模板执行默认私聊 Replyer 子路径。默认身份和风格未换词，没有模拟 Planner 或伪造参考；空参考是 Replyer API 允许的参数，但不等同需要非空参考的完整 Planner 工具链。[^mai]
- 溪语固定 `06928e2dbccf438109a9eeae80086bb12f729fd3`，直接调用原 `buildSystemPrompt`，保留默认角色和初始关系。没有运行首轮、情绪/事实/场景更新、inner OS 和输出守卫。分段符仍保留在原始模型输出中。[^xiyu]

完整原文件和许可已保存于实验目录，附 SHA-256 校验。必要的历史适配、宿主路由及传输胶水独立于原文，两个上游组没有混入宿主默认角色、示例、世界书或历史后提示。原系统角色按现有套餐适配器转换成 developer，内容和顺序保留；temperature、top_p、输出上限不被该传输支持，记录原设置但没有声称照原参数运行。

离线额外构造 14 轮完整历史验证原文组的 29 条历史/当前消息仍在，检查宿主 canary、路由标记和默认续写提示没有进入实际请求。每次真实调用保存原消息、实际 wire 请求、哈希、原始输出和完成状态。

## 对话观察

本轮 MaiBot 的用词和接话更接近日常闲聊，当前内置角色仍明显受灯塔设定影响，溪语更常使用分段和照顾对方的表达。三组均在短回应、输入纠正、不需要建议、意见分歧和结束对话等场景产生了完整回复。

这些是阅读本轮记录后的定性观察，不是自然度分数，也不是完整产品排名。三组原人设不同，只做过一次固定场景运行，未进行匿名人类盲测。需要用户亲自阅读并聊天后再决定基础方案；本轮没有混合提示词，也没有修改上游规则来迎合结果。
