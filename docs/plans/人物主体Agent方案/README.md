# 人物主体 Agent 方案

更新：2026-10-26。状态：**新项目设计已形成，尚未实施或验证新系统行为**。以持续生活、共享人物和真实平台影响为目标；不受现有 Between、SillyTavern、技术栈或已投入代码约束。本轮没有删除运行代码、迁移数据、操作社交账号或调用收费人物模型。

## 状态和维护方式

- 以新项目设计，不受现有 Between 代码、技术栈、接口、SillyTavern 或既有投入约束；允许方案选择完全重做，不因此立即删除现有实现。
- 遵守已经确认的决定与本目录的愿望原文。对于未决设计，用户授权助手依据目标、核心原则和参考项目自行选择，记录充分理由、替代方案、取舍、风险和验证办法；区分用户确认与本轮设计选择，不把授权选型写成行为效果已验证。
- 主要机制应来自可核查的开源实现，尽量复用成熟方案。每个设计关联来源项目、固定版本、具体机制及代码或提示词位置，并标明原样复用、适配或自主补充。证据不足时明确缺口，不用推论伪装上游实现；实际复用的核心提示词继续遵守原样保留要求。
- 方案拆为多个专题，由本文件统一导航；共同概念、事实来源规则和数据约定各自只维护一份，其他专题引用。开源源码证据继续维护在研究资料库，方案记录为什么采用、如何适配及所付代价。
- 本目录取代旧单篇运行方案，02维护决定状态，03维护共用数据语义，04–08及12各自维护机制，09维护验收标准，11及人物资料目录维护原创底稿。新证据改变设计时修改原专题和02，不另开第二份当前决定。
- 方案里的流程和对话例子是推演。未来实现、真实运行与体验结论另留可追查记录，不能把文档验收或旧项目测试当作新系统行为通过。
- 三平台能力、职业一手资料、情绪适配和自然对话仍有明确验证门槛；没有达到时保持未完成，不用界面演示或文字声明代替真实动作。

平台工具与职业资料的本轮补查单独见[补查报告](../../research/人物项目机制/平台工具与内容生活补查.md)。[返回仓库文档总索引](../../README.md)。
