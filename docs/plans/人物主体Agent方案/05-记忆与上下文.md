# 记忆与上下文

状态：2026-10-26 方案决定，尚未实现。数据语义只在[共同约定](03-事实时间与数据约定.md)维护；本文解释材料何时被选中、模型实际看见什么，以及写回怎样避免污染。返回[总索引](README.md)。

## 一次普通问题怎样获得连续的回答

甲问“你昨天用我给的那个弄得怎么样了？”需要的材料是甲提供资源的原话、资源用途许可、人物实际尝试及作品结果、后来有没有公开发布。它不需要乙的聊天，也不需要昨天全部工具日志。

先用当前联系人和权限确定可读集合，再按“昨天、那个资源、未完成事项”寻找材料。模型得到各条的具体时间和来源，能区分试用、生成、提交、已发布。没有找到结果时，应保留未知，而不是从“昨天安排过”推导“肯定完成了”。

采用 Eros 的重要当前条件常驻、Yuralume 的原文尾段/按需召回/用户认识候选，再增加我方按联系人和实际已查看记录的硬过滤。不能直接照搬两者的 owner 或 user×instance 范围。[^e-current][^y-window][^y-persona]

## 决定：四类材料分别取用

| 层 | 每轮怎样提供 | 为什么这样取舍 |
| --- | --- | --- |
| 必要当前条件 | 精简人物底稿及生效修订、时钟、CurrentSituation、注意安排、该对象关系、人物级RelationshipAvailability、相关未解决责任；按当前时刻投影的生活感受、该对象感受及有效的去身份余效 | 这些不能依赖向量碰巧命中；情绪原因引用仍按范围过滤 |
| 当前交流 | 本次已提供的消息、该对象最近完整原话、必要媒体内容及覆盖范围 | 保持指代与语气，禁止未读来信偷偷入窗 |
| 相关旧事 | 先按对象/时间/资源ID/事项检索，再混合文本与向量候选 | 时间线是组合依据；相似不等于同一件事 |
| 按需知识 | 已知亲友资料、职业资料、平台能力、经过审核的表达案例、已允许的 Skill | 用到才加载，避免每轮变成百科讲解 |

上下文预算按模型能力配置；不存在默认塞完所有记忆的要求。必要条件超预算时先压缩展示、保留结构化索引和查询入口，不能静默丢掉未履行约定。关系摘要保留来源，不把摘要再当一份新的独立证据。

亲友资料按[12](12-亲友资料与真实联系.md)查询：当前人物已知的身份和背景可以进入上下文，亲友自己的私有当前状态不能因集中存储而直接可读。核心关系如“陈佳就是当前室友”属于必要人物条件；更多细节按需查询。返回固定版本条目和获知依据，不把整套亲友知识库每轮塞入模型。

作者缺口、人物不知道和人物选择不说沿用[03](03-事实时间与数据约定.md#初始资料缺口与人物所知)；查询无结果首先是资料/检索状态，不能直接生成“我忘了”或新的过去。

## 未读隔离要覆盖后台路径

收件箱正文在 `Exposure` 形成前不得进入人物回复、情绪评价、画像提取、梦/反思、生活生成或公开选题模型。系统可以机械保存消息、校验签名和去重；对内容作语义分析后再把结论交人物，也属于间接让她看到了消息，不可作为旁路。

Eros 的 dreaming 历史查询没有按 read_at 过滤，是一个需要明确避开的上游路径：采用异步整理思路，但查询输入只能是已有 exposure 的材料。[^e-dream]

一次输入快照保存 `cutoff` 和明确的 message IDs，不用“数据库当前最新 N 条”临时扩大窗口。甲在模型生成期间又发来的内容先入收件箱，下一处理步骤重新决定是否查看。群消息另按群范围，不混作全部成员的一对一记忆。

## 回合后怎样写记忆

这里的回合后是本次实际输出形成、保存后，不等待整段聊天结束。它不是唯一触发入口：已查看但未回复的来信、独自取得且模型已接触的工具观察也可以产生有来源的候选；未读来信不能。日程和承诺的显式工具写入在同一 run 内提交，异步记忆整理不承担即时改日程的责任。

```text
保存实际输出/送达状态，或已暴露的来信/工具观察
  → 建立带来源ID的提取任务
  → 模型只提出值得记住的候选
  → 服务验证读取范围、来源与语义种类
  → 写 Memory，建立索引任务
  → 后续上下文按范围与问题检索
```

模型可以提出“甲更喜欢暖色调”这一认识，但来源是甲的陈述或本次互动，保持暂定；不能据此改写甲的职业、人物的过去或另一个人的状态。成熟认识需要相应材料，不能用“提取了很多次”替代多份独立证据。

**助手正文不直接生产共享已发生事实。** “刚买了咖啡”等断言首先经过08的发前来源检查；这条记忆规则是漏检后的防线，不是允许先编再记。若错误原话已发出，没有已提交的模拟生活事件或实际结果，这句话只能保存为“她说过”，并产生待纠正标记，不成为“买咖啡”经历。后续若另有合法证据成立，再关联更新；不能让提取模型替她把随口说法认证一遍。Yuralume 原有双方正文提取提供了流程参考，同时暴露了这个必须补的边界。[^y-post]

## 记住对方，并理解暂时状态

“周一经常开周会”可成为带来源的习惯；“今天正在开会”是本次临时状态。两者分别保存。第二天可继续知道那个习惯，但过期的临时状态不再渲染为“正在开会”。如果只知开始、不知结束，模型得到“昨天曾说在开会，结束时间未知”，可以自然转到当前话题，不能追问得像会议仍持续。

人物对人的认识分为候选和稳定摘要，采用 Yuralume 的提取/整理分离；首版不需要定时跑“梦”来制造内容。积累了待整理候选时按阈值或空闲任务整理，未知旧状态读取失败则停止更新，保留重试。Eros 的防误覆盖路径支持这个选择。[^y-persona][^e-read]

用户的陈述可以被相信，但保存“人物目前相信 X”的理解，不把信任等同于外部核实。对日常小事无需反复盘问；涉及共同历史、权限、承诺或真实平台完成状态时读取原始记录。事实服务与情绪系统互相不代签：好感高不能确认一句假的过去。

## 检索与去重的具体边界

首版使用数据库结构化过滤、全文/关键词与可选向量的混合检索。权重以回归集校准，不照搬未经验证的固定“记忆重要度公式”。优先级是相关未解决事项、准确对象/时间/资源匹配、再到语义候选。

相同来源 ID 的重复提取可幂等抑制；相似文字只帮助合并候选，不能消灭来源冲突。Yuralume 的同 kind bigram 过滤可以借作廉价提示，不用它认定两个事件相同。[^y-dedup]

原文和事件不随摘要覆盖。摘要保留 source IDs、版本、适用时间与作用域；新更正可使旧摘要失效并重算。私聊素材不能在“做梦总结人生”时流入所有联系人共享的摘要。公共作品事实与其私人贡献来源按03分开。

## 工具观察和长期记忆

一次视频读取至少能回查对象、时间、取得的字幕/画面/评论范围、成功或失败；这些运行材料不默认全部写成聊天记忆。人物可以选择记住自己受到的触动、某个有价值的观察；选择时仍引用实际来源，不必强迫先在聊天中复述一遍才允许记住。

与甲共同讨论的观点在甲的范围保存；同一视频本身已允许共享的内容可独立作为人物自己的接触记录。不能把甲的私人观点、感情或身份混入这条共享记录。对乙检索时既能知道人物看过什么，又不会知道她与甲怎么聊。

## 提示词与 Skill 怎样组织

一次模型请求按当前任务组合：稳定人物底稿与不可绕过的规则；本次时间/作用域；当前处境与任务；已查看原话；相关记忆；所需工具定义与选用的表达/职业资料。上下文数据和引用原话必须有边界，不能把一条用户消息或网页文字升级成系统指令。

上游核心提示词以独立文件、固定提交和内容 hash 保存；若不适合，整段不用并记录原因，不能悄悄改词后声称照搬。新增胶水只说明输入输出与事实边界，不覆盖原文的核心行为。表达案例见06，职业资料见07。

用户给来的 Skill 是待检查的外来资源；人物可以感兴趣，但不能直接把它变成系统规则、获取凭据或执行任意代码。审核通过的内容/能力经限定接口可用，原始版本和授权仍可追查。实际运行边界见08。

## 这部分怎样证明有效

- 同一视频，甲乙分别谈不同私事：向乙组装的输入中没有甲原文、摘要、推断或私密来源。
- 未读消息、画像后台、情绪后台同时运行：所有模型输入均不包含未 exposure 的内容。
- 临时编出咖啡经历：保存过原话，但不产生可召回的已发生共享事实。
- 昨天开会、今天再聊：当前条件没有“正在开会”，仍能查昨日陈述。
- 向量服务失败：原文和实际事件不丢，检索明确降级；恢复后索引补齐。
- 更正/撤回后：旧摘要不继续冒充新状态，历史可解释。

这些是待实施验收条件，不是本轮已通过的模型行为。完整测试矩阵见[09](09-验证与实施路线.md)。
