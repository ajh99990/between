## 2. 来信、事实和输入：具体保存与确认什么

### D-M01：来信与实际提供

采用现行03的顺序，不再新加一套“已读状态机”：通道入口保存 `Message + InboxItem + received Event`；只有明确授权才取得正文；最终请求材料清单保存后派发；取得有效输出/可核实处理回执，才确认 `Exposure`。准备、取得正文、HTTP受理都不能提前确认。

建议的最小持久约束：

- 入站消息唯一键使用适配器声明的 `(channel, account_binding, external_id_scope, external_message_id)`；需要会话范围的平台把会话纳入scope。正文相同不是重复依据。
- 每个网络尝试有独立 `request_attempt_id`，归属稳定逻辑步骤；材料项包括版本、实际片段与hash。Exposure唯一到“请求尝试+材料版本+片段”，同一次回执重复到达不重复写入。
- 确认提供与“是否允许执行旧提案”分开。晚到输出可能证明材料曾提供过，却已失去步骤资格；可以补记确认，不能补执行旧动作。
- 首次正文不得先交给后台摘要、embedding、情绪或主题分类。读取接口只开放给获准的当前下一逻辑步骤；后处理只消费已确认提供范围。

这一分工沿用03；本轮补充的是数据库约束与适配验收重点，不冒称某提供方会给出精确人类“阅读时刻”。验收必须含请求未发、发出未知、流中断、确认后崩溃、迟到及撤权六条路径。

### D-M03：物理存储与查询

不把每个名词拆成微服务，也不把所有内容塞进可任意覆盖的JSON。建议一个PG数据库按职责分组：消息及提供记录；生活/计划/事件/主张；关系/感受/承诺；运行/唤醒/操作/outbox；素材/发布/许可；派生记忆与索引。框架checkpoint另置命名空间。领域核心字段是可索引列，来源正文/模型提议可用版本化JSON。

`facts.query` 的建议输入是人物运行身份由宿主固定、对象引用、时间范围、材料种类、可选问题；返回记录ID、原文位置、来源/含义、发生与适用时间、版本及冲突。**有结果不等于已认证为真。** “甲说周一开会”按 reported 返回；“她确实发过这条消息”查出站结果；“她早上已去拍摄”须查模拟生活事件，不能从聊天自述倒造。复杂问句可让模型查询多次，不新造一个万能真伪模型。

UTC存储、人物时区解释、“今天”绑定当时日期和 `[start,end)` 继续遵守[03](../03-事实时间与数据约定.md)。完整DDL要随框架切片一并验收；当前文档给的是物理分组与关键约束，不伪称迁移已经存在。

### D-M07：当前输入与cutoff

请求快照用服务端已提交的消息序号水位加**精确消息ID/版本清单**，不只使用可能同秒重叠的时间戳。之后到达的消息进入下一次请求；水位之前的未读正文也不因此自动获准。框架ID合并不替代这层授权。具体原话窗口、默认材料和工作轨迹见[02答复](02-连续对话与生活变化怎样衔接.md)，记忆被检索与实际加入输入的区别见[03答复](03-事件与记忆如何真正落地.md)。

## 3. 生活、注意与责任：避免机械规定人物行为

### D-M02：注意规则重叠

建议把一次注意决定保存成一个有版本的策略，内部支持全局、渠道、联系人范围。更具体范围可以覆盖宽范围，**但只有在模型明确提交例外时才生效**。不让几小时前的“甲可通知”悄悄穿透新设的“现在全部不看”。

例如模型提交“接下来半小时不看普通消息，但保留甲的通知”时，一次提交全局规则和甲的例外，例外引用被覆盖的规则版本。随后模型改成“所有消息都不看”，未明确保留的旧例外随旧版本失效。服务负责解释这一份策略、校验范围和版本；不是根据正文的“紧急”关键词替模型作例外。相同范围只能有一个当前有效决定，历史仍保存。

到期只产生处理机会；模型可以选择查看、继续不看或修改策略。新规则替代旧复看任务时保留替代关系，不能把已读待办或承诺一起取消。聊天中复看到期的具体处理见[02答复](02-连续对话与生活变化怎样衔接.md)。数据库扫描间隔只是工程配置，建议隔离切片先用1秒轮询，测真实延迟再调整；它不意味着每秒调用模型，也不是用户批准的SLA。

### D-M04：起始处境、日程空档与过去保护

实例启用时使用11的候选底稿，再建立一份带真实启用时间、来源为模拟的当前处境；例如“在住处整理照片，稍后复看”。这是实例配置示例，**本轮没有把它写成她今天实际做过的事**。日程习惯不自动转成事件，空档也不准各私聊自行补生活。

服务接口建议保留 `life.current/advance`、`schedule.read/propose_change/commit_change`：每次修改带期望版本、稳定操作ID、变化理由和来源；进行中安排只改服务端当前时刻之后的部分。生活事件、处境版本和必要唤醒同事务保存。状态过期时先统一复核；失败则明确最后已知，不让每个联系人产生一个新解释。准确职责已有[04](../04-生活推进与注意管理.md)，新增基础只负责调用和恢复，不替生活服务做决定。

### D-M05：自然话语如何成为承诺

建议把待发文本与 `commitment_proposals` 放在同一个响应提案中，而不是发送完再等后台猜。模型说“八点发给你”时，提案包含文本、对象、未来行为、条件、时间解释与来源；窄检查同时核对文本是否存在未登记承诺。服务先保存内部待办及出站意图，发送结果再决定是否已有对外承诺依据。

```text
提案：回复“八点发给你” + 对甲发送作品的责任
事务：待办 + 检查通过的消息版本 + outbox
发送失败：内部待办仍在；没有“甲已收到承诺”的记录
发送unknown：保留待核查，不重复发；承诺对外成立状态保持未知
确认发送/送达：按通道实际依据记录，不能冒充已读
到期：作品未完成仍欠这件事；聊天中一句“在干嘛”不消除它
```

反例是只在回复正文中答应，接口没有写成功；另一反例是为保证保存，把`known_pending`直接叫`expressed_promise`。上游Yuralume提供延期事项与后续处理的参考，**上述领域提交和出站协调是我方适配**，依据见[04 §4–5](../04-生活推进与注意管理.md)和[08 §5](../08-运行架构与工具契约.md)。语义漏检仍需真实对话验收，不能用专用接口测试保证每种自然表达都被识别。

## 4. 感受、记忆与表达：哪些可以复用，哪些尚无效果证据

### D-M06：记忆与认识

完整回答在[03答复](03-事件与记忆如何真正落地.md)。关键是分别验证：机械记录成功、获准语义提取、候选校验与保存、索引可用、后续主题召回、实际输入。参数不能只写“以后调整”：该篇给出首轮提取触发与查询建议、重复任务/更正传播及具体反例；任何实验初值都不能被称为人物心理常数。

### D-M08：EE保留清单与退出条件

本轮不以新框架选型推翻现行EE方案，也不重新创造一个情绪引擎。以[06 §5](../06-情绪关系与表达.md)及其固定源码为适配基线：

| 保留/调整 | 具体范围 |
| --- | --- |
| 保留 | PAD/pulse状态计算、`record_turn(state, ...)`这类接收/返回状态的函数、证据ID与显式结算逻辑；用独立测试核对调用参数及副作用 |
| 替换宿主边界 | 权威状态从PG读副本并计算，再以版本、事件、锚点、证据同事务提交；不保留另一份可独立写的EE JSON真相 |
| 不直接启用 | 按聊天轮数恢复、缺席自动降信任；不让工具调用多的人恢复更快，也不因用户没上线惩罚关系 |
| 我方扩展 | self与逐人状态、有限余效、独立时间锚点、短评价批次；不把这些归给上游现成多人功能 |
| 旧测试的边界 | 可复用纯计算/结构测试；原文件保存、旧时钟、单关系生命周期测试要另核对；原96项离线通过不是本系统适配通过 |

参数表在实施时必须有“上游版本与原值、采用/改值、理由、测试场景、当前结论”，不能先拍一组‘科学’数值。用同一事件序列比较EE与文字状态基线：烦躁是否延续、道歉是否缓和但不凭空增加信任、切换联系人是否泄露原因、长等待是否正确推进。如果EE没有可观察收益，记录结果后讨论停用数值部分；不能为了既有投入宣布其更拟人。

### D-M09：表达材料与窄检查

装载清单由[06 §7](../06-情绪关系与表达.md)的原文/原创/胶水区分继续发展：每块明确来源SHA、文件、字节hash、适用场景、冲突及采用状态。已有QQbot七行摘录是可选措辞素材；原创反面案例有旧实验依据；v0.2具体示例没有整体胜出，不能自动升级为最终人格核心。原文块冲突时选择停用或请用户决定，不能改写后仍称原样。

每次请求建议按“不可变规则与原文模块 → 当前人物/时间/背景 → 真实消息与本任务轨迹 → 已获准相关资料”装配，记录最终载荷；平台与提供方的role限制由适配器显式处理。案例检索返回场景、前后文、坏例、问题、正例和例外条件，不提供全局禁词替换表。首版实验建议最多一次针对性修正，仍不合格则暂不投递、保留原因；这是成本与重复改写的工程取舍，可校准，不是人物不能表达情绪。

## 5. 工具、资源、发布与管理

### D-M10：统一业务调用外壳

基础采用建议见[01](01-Agent承载基础怎么选.md)。模型可见参数只包括行动需要的内容；人物ID、当前发送对象、授权、逻辑步骤、操作ID由宿主绑定，不能让模型自由伪造。

```text
宿主调用：run_id / step_id / operation_id / expected_revisions / arguments
结果：operation_id / status / records[id, revision] / errors / next_action_hint
典型拒绝：permission_denied、not_exposed、revision_conflict、past_immutable
外部结果：confirmed、failed、unknown，另附平台实际状态
```

这些是拟议统一语义，不是所有工具都返回同样巨大对象。版本冲突返回可重新读取的记录引用；过去修改返回被保护区间；权限拒绝不返回无权资料正文。只读可做有限退避重试，写入由稳定操作ID查询结果，未知状态优先核对。每次模型调用有总截止时间和用量记录，具体值按选定提供方与隔离切片测量；未定不是采用无限等待。

模型请求不跨数据库事务持锁；checkpoint与领域提交分开，用幂等业务操作衔接。完整迁移、错误码与故障恢复测试应随后续切片验证，不在本轮虚构接口已经可调用。

### D-M11：用户资源与作品

用户发来的Skill/图片先形成带来源和版本的资源记录。资料读取、试用方法、执行代码、使用素材、公开作品是不同授权。建议首版仅允许已安装且受限的创作执行器：只接输入文件与任务，产出文件/hash/执行结果；不让外来Skill安装包修改主角色系统提示或读取账号凭据。

许可记录至少关联资源版本、允许用途/平台、是否可公开、给出许可的依据、撤销时间和版本；私人贡献单独留在私有范围。模型可以不喜欢、不采用、稍后再试；采用了才记录具体影响作品的关系。它不是“收到礼物就加好感”的奖励通道。[07 P05](../07-社交平台与内容生活.md)已有此边界，本轮把执行入口与许可记录落点说清。

### D-M12：平台发布

发布系列和稳定意图继续采用[08 §5](../08-运行架构与工具契约.md)，不可因框架重试换一个新ID重发。适配器逐动作返回：是否提交、平台对象ID、审核/公开状态、证据取得方式及观察者范围。请求成功但只受理审核，不算公开；读不回也不能直接算失败重试。

“日程结束必须有帖子”应落实为：发布任务必须有真实完成或明确未完成状态。时间到了但失败，模型应根据结果选择重试、改期或放弃；不能让计划时间驱动一个假的成功。发布成功也不代表已经按约通知某位用户。

### D-M13：管理与删除

管理端先提供排障必需的记录及暂停/撤销能力，不以重做漂亮后台替代核心。建议按人物、联系人、run、操作ID查实际输入清单、状态版本和结果；凭据仅显示引用。暂停阻止新决策及未派发动作，已经发生或unknown动作仍可核查。

删除从来源ID沿派生关系处理，不只删向量或换昵称。还须覆盖**框架checkpoint、提取任务、待发载荷、工具缓存、请求快照、备份保留规则**；重启后的旧任务不能把正文写回来。只保留必要非正文防重标识。过去日程保护不等于永久保存个人信息。保留期和真实用户数据处理策略是接入前配置，不能用本轮研究授权无限存储。

## 7. 效果问题怎样得到答案

| 编号 | 必须取得的证据与反例 |
| --- | --- |
| D-V01 确定性约束 | 固定时钟、PG事务/唯一约束、故障注入、请求清单；验证过去保护、未读、重复提交、撤权、恢复。构建或脚手架存在都不算 |
