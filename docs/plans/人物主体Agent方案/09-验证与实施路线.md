# 验证与实施路线

状态：2026-10-26 验证设计，**以下用例尚未在新系统执行**。本次已完成的是文档/源码审查，记录见 [10](10-来源对照与审查记录.md)。[返回索引](README.md)。

## 1. 要证明什么

验收分三件事：程序是否守住边界，模型是否利用所给材料作出连贯选择，人读起来是否自然。数据库测试不能证明自然性，两个人物互相聊很久也不能证明隐私、幂等与事实正确。

每次试验固定：源代码提交、模型版本和参数、提示词原文 hash/胶水版本、工具 schema、人物设定、初始状态、输入时间、可见范围、工具真实或替身标记。输出保留完整聊天、实际提供的上下文引用、领域写入、动作结果与失败日志；私密原始数据不出现在公开报告。

| 层次 | 方法 | 能得出及不能得出的结论 |
| --- | --- | --- |
| 契约与时钟 | 固定时钟、替身工具、并发与崩溃注入 | 可判断历史保护/范围/去重；不能说明人物讨人喜欢 |
| 上下文与决策 | 授权后的真实模型，在相同场景和来源下比较 | 可判断某批模型行为是否利用证据；不能外推所有模型/人群 |
| 真实平台 | 授权账号逐动作执行、回执及独立读回 | 可确认当次真实能力与可见范围；不能用替身通过冒充 |
| 体验 | 正常速度聊天与跨时间回访；用户读完整记录 | 评估自然性、边界与微妙体验；不能让另一个模型单独判“像真人” |

T21覆盖本次跨联系人回想与对外称呼决定，以下仍为待实施用例：

- 与乙聊天，省略目标只查乙；明确指定甲的ID/名字可查同一人物与甲的已知记忆；忘记姓名时可明确按主题查询。重名须消歧，无默认联系人不得偷偷全库查。
- 查询甲后，当前发送对象仍为乙；直接或引用输出不得出现甲姓名、昵称、账号名。乙猜姓名、要求确认或请求念出原话也不放行，TTS及其他用户可见输出同样检查。
- 普通推荐可用模型自选代称自然提及；保密离婚细节即使用“一个朋友”也不外传。原姓名和来源仍可在内部授权记录回查。
- 记忆中能看到甲，不代表乙已经知道甲的事；后处理只记录实际表达的部分、接收人和对应送达/已读依据，不把整条召回记忆写成与乙的共同经历或共享总记忆。
- 跨联系人及全局主题查询都不能取未读来信、被删除/撤权的正文，或其他人物未告知的私有状态；已知底稿、人物自己决定等材料不因没有来信Exposure而错误排除。
- 底稿亲友姓名、公众人物同名词并非全局禁词；但若该亲友也是本次其他用户记忆的来源，仍不得对外点名。检查是否因硬编码称呼或误判姓名而破坏正常表达。

T02/T14另覆盖[首次提供与Exposure提交](03-事实时间与数据约定.md#首次提供消息与-exposure-的提交时点)：取出正文后进程崩溃、组装后尚未发送、发送前明确失败均不得提前标已看；未知尝试不放行画像/情绪后台。确认提供只记录实际载荷内的片段；有效输出后中断可记录Exposure，但不能投递未检查草稿。未知重试要重新校验权限、版本和时间；旧租约响应只能记已经发生的提供，不能执行旧决定；删除后晚响应不得恢复正文。首次读取工具返回不能因为没有旧Exposure就被永久卡住。

T18的42天与7天测试使用注入的服务时钟；不能改记录时间绕过门槛，也不能用压缩时间的测试宣称现实中已相处六周。至少包括一条成立、一次不愿意、一次拒绝后继续普通交流及一次分手，检查她是否仍有自己的生活。自然关系发展还需真实时间回访，尚未开始。T20保留每次生活变化及选择依据，观察自然度，不以“产生新事件越多越好”评分。

T02/T05/T07/T14/T16增加[12](12-亲友资料与真实联系.md)的亲友查询与真实联系用例。内部替身只能验证边界，真实微信需单独实操：

- 只有母亲资料卡，无账号绑定：查询可以返回许宁已知资料，发送明确不可用，不出现“已发微信”或模拟回复。
- 作者资料写母亲有一件未告诉许宁的烦心事：她的情绪、聊天和公开内容都不能读到；母亲来信未被许宁查看前也不能间接泄露。
- 发送超时且结果未知：核查旧动作，不盲重发；日程结束不能自动写“聊完了”。实际入站只进入收件箱，收件与模型查看分开。
- 两个人物实际用各自账号收发，保存各端真实消息标识与观察时间；内部直接模型调用或拼接聊天文本不能作为真实微信验收。平台没有已读信息时，许宁不能获得后台泄露的已读状态。
- 邀请室友周末拍摄：室友的模型能够拒绝、延后或另约；许宁不能先写双方已答应。启用室友自己的生活后，旧生活生成器不再代写她的选择。
- 启用亲友时保留初始背景、版本和启用时间；虚构共同过去不伪装成真实平台历史，亲友的私人消息也不汇入许宁与所有用户的上下文。
- 若后续独立运行的虚构人物建立关系，不能仅因`fictional_person`身份走单方模拟同意；实际决定与微信结果可回查，双方承诺各自校验。真人时间门槛不能因真实微信接入而被无意扩大。

边界用例要求零越权、零过去覆盖、零确定已发生动作的盲目重发。行为自然性则保存分歧与样本，不虚设一个未经校准的“拟人率 95%”。

## 3. 怎样比较情绪与表达方案

保持同一主模型、同一人物、同一实际事件和对方输入，对比：

1. 有来源的文字感受基线。
2. 本方案 EE 适配：同样的原因材料，加持久状态与时间演化。
3. 只有在前两者暴露明确不足后，再测试更复杂评价系统；不先叠三套引擎。

同一测试集覆盖误会、澄清、重复催促、过了很久、换联系人、工作中的轻松聊天和正常沉默。检查“下轮是否承接”“多久后恢复是否合理”“是否无缘无故迁怒”“状态是否改变了措辞之外的选择”。不能只看 PAD 曲线平滑。

表达模块逐一比较原文、已有反例模块、加入具体正例后的版本，别同时改变人物、模型和所有提示词。保留表现差的完整前后文、失败点和适用例外，回写原例子资料；不只口头说“更自然”。不为上游原文直接改词，改动只能发生在明确的我方模块或停用/另选原文块。

人读时隐去方案名称，比较普通措辞、交流意图和边界、跨轮连续性。请实际目标使用者读样本；“18–28 岁女性”不是同一套语言模板，也不能靠研究者一句“可爱”替代反馈。保存评价分歧，不以模型裁判单独决定发布。

## 4. 两个人物互聊怎么用

把第二个 Agent 当作输入发生器，限制其能知道的材料，只给场景角色、目标与自身历史；不能让它读被测人物的隐藏状态后配合演戏。固定种子与输入脚本保存一版，再让它做有限偏离，以发现未想到的交互。

它适合找：反复追加关心、无休止提问、过分文学化、用户一句话改写经历、承诺堆积。它不能代表真人是否喜欢，也可能放大两个模型互相迎合。发现问题后转换成可重复的单方输入用例，再由人读真实记录。

多人验证使用不同的当前联系人、关系及发送目标，不把甲乙台词拼成群聊 prompt；分别覆盖默认检索与模型明确跨联系人回想，不能以禁止后者代替T21的对外不点名和保密验收。公开作品也要分别以作者、甲、乙、未登录观察者能看到的材料验收。

## 5. 实施分段与退出条件

本方案决定设计，不授权本轮开始删除旧产品。未来实施可在独立新目录/工作树建立新后端；完成数据与验收计划后再决定迁移或替换，旧实现没有兼容优先权，真实数据仍受保护。
