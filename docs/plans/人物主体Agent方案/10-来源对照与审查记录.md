## 4. 交叉审查已经导致的修改

| 发现 | 修正及理由 |
| --- | --- |
| AffectState用self/relationship作scope，与统一权限枚举冲突 | 统一character/contact权限，另设affect_context；状态类别不能替代谁能读取 |
| 感受与余效写入了，但上下文列表缺消费者 | 05明确每轮提供时间投影后的生活/当前对象感受与合法余效，不引入私有原因 |
| 误会纠正只重写解释，已扣信任/外溢却仍生效 | 证据失效、信任重建、终止失效原因的外溢；PAD/pulse通过纠正事件继续变化，不回滚历史；不是给一次道歉奖励 |
| 记忆入口只写回合后，却允许没说出口的观察 | 明确已暴露来信及独自工具观察也可产生候选；未读仍禁止 |
| EE批次等整个长run结束才关闭 | 改短evaluation_batch，工具等待前关闭；来源键跨批次防重 |
| 工具路径名称容易被理解为现成多步循环 | 重新读源码，明确Yuralume是一次工具两遍生成；多步与恢复是新增适配 |
| 一个整run占住人物会卡住正常交流 | 08采用短决策步骤/短提交，慢工具让出运行，恢复时重建当前上下文 |
| 已有公开素材不等于他人可以获知私人来由 | 03增加具体用途许可、可识别细节检查与独立公共记录，来源引用仍受权限 |
| 版本没变但模型生成期间处境已经过期 | read_set加入时间边界和许可版本；提交/派发按当前时钟复核，不仅比较revision |
| EE文件写入与宿主数据库可能成为两份状态权威 | 复核record_turn接收/返回state对象、CLI另行save_state；选核心函数计算副本，再统一数据库事务提交 |

## 5. OpenCode独立质询

使用 `opencode-go/deepseek-v4.1-flash`、`max`、只读plan模式；同一会话先审目标/选型，再针对并发、范围与授权提出质询。其意见不是事实来源，也没有取代根Agent核查。

| 讨论议题 | 根Agent判断 |
| --- | --- |
| 单体+数据库任务，避免先建微服务/全量事件溯源 | 采纳，降低初版跨服务一致性负担，具体栈属于我方选择 |
| 一个活动run占住人物 | 不按此字面采用；改为短步骤提交，等待工具可并行其他run，重读实际依赖 |
| 首版只做一个平台 | 不采纳为范围缩减；可以阶段先证明一条链，三平台首版门槛仍完整 |
| 聊天正文永远不能改权威状态 | 修正过宽说法；同run显式领域工具可写计划/主观状态，禁止的是正文提取自动认证已发生事实 |
| 是否需要总可信度评分 | 共同选择不采用；保存来源、含义、时间、范围和具体事项，各事项分别判断证据 |
| 公开作品怎样处理私密来由 | 采纳超出去名的要求；补用途授权、可重识别检查、私人来源链和独立公共载荷 |
| 恢复时应保留什么 | 采纳保存目标/步骤/来源并重建当前上下文；冻结的prompt不能作恢复后的世界，已执行副作用不重播 |
