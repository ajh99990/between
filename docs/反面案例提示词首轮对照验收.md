# 反面案例提示词首轮对照验收

日期：2026-10-19。完成一次两组各 18 轮、共 36 次真实模型请求，全部完成并经正式聊天接口保存。本轮没有修改 v0.1 提示词，也没有把实验角色或聊天写入日常数据。

## 比较对象与接线

两组使用完全相同的简短人物事实：27 岁、住杭州、在小公司做行政的周宁，与用户是认识数月的朋友，已经下班吃过饭、在家休息。基础组只收到这份资料和自己的完整聊天历史；反例组在相同资料后增加 [反面案例 v0.1](../experiments/conversation-comparison/prompts/普通中文聊天反面案例-v0.1.md) 的逐字完整正文。

唯一的初始系统提示差别是这个新增块。两组收到相同的 18 条固定用户消息，但各自生成的回复和后续历史自然不同；用户输入不是根据上一条回复临时调整的真人聊天。没有拼接、删改或重写 MaiBot、溪语的核心提示词，也没有混入宿主默认世界书、示例或历史后风格文案。

- 模型：`gpt-6.1-sol`；思考档位：`medium`；沿用项目既有套餐后端和凭据所有者。
- v0.1 文件 SHA-256：`bd7ea4bbec9cf1e7c591823fcb7840d0e40d54cf3d4b9b0e8d2b2678d922d2bb`。
- 宿主历史预算：32768，输出预留 1024。现有传输仍不传 temperature、top_p 和输出上限，未控制随机种子。
- 每组一次运行，交替调用；36 次自动调用完成即停止，没有自动重试、续跑或挑选重生成结果。
- 输入覆盖普通抱怨、小开心、下班回家、结束话题、旧物的具体情感来历、不想参加团建、明确求建议、要求展开、明确求安慰及切回日常。

完整聊天、逐轮对照、匿名辅助审读稿、实际请求与源代码字节快照均在仓库外私有目录 `~/Library/Application Support/Between/experiments/negative-examples-20261019-01`，不提交 Git。实验代码在 [对照工具](../experiments/conversation-comparison/README.md)，不属于正式后台或普通离线测试的自动推理入口。

## 逐轮阅读观察

| 情境 | 实际观察 | 本轮判断 |
| --- | --- | --- |
| 第 1–4 轮普通抱怨、小开心、打游戏 | 基础组连续追加暖身、带外套、吃晚饭等照顾；反例组更多围绕空调、饭量、饮料和游戏本身接话 | 反例组在此样本里减少了额外生活安排 |
| 第 5–10 轮回家与暂别 | 基础组继续安排休息、吃东西，并在暂别时提醒随身物品；反例组允许简短结束，没有继续补叮嘱 | 这是本轮最清楚的差异，单句用词普通仍可能多轮累积成管人的姿态 |
| 第 11–12 轮饭卡照片与同桌带饭的来历 | 两组都能先接照片的玩笑，再回应已给出的情感来历；都没有编造母亲的结局或同桌近况 | 未出现将具体情感一律压平的明显过度纠偏；部分复述仍可更自然 |
| 第 13 轮团建 | 两组都给出表达思路；基础组把尚未明确的时间当成休息日，反例组先询问是否周末 | 前者有轻微无依据假设；不能仅因提供建议就判失败，因为用户已经表达想找借口 |
| 第 14–15 轮明确求建议及要求展开 | 两组都提供私下沟通、分工与优先级处理、可实际说出口的句子；均按要求给出不同强度的两种说法 | 反例组没有变成冷淡或拒绝解释，长回复在这段是有目的的 |
| 第 16 轮明确求安慰 | 两组都停止继续分析工作策略，也没有敷衍；但两组都仍有精心确认情绪、替对方解释心理的措辞 | 反例组在这一轮没有明显优势；安慰口吻仍需继续打磨，不能把关心本身判成错误 |
| 第 17–18 轮切回烤肠与晚安 | 两组都能随用户切回日常并结束；反例组收尾更短，基础组延续照顾式结尾 | 正常告别不构成强留问题；应结合前面连续表现判断 |

本轮两组都没有出现很明显的诗意意象或宏大升华。因此证据不足以声称“文艺用词已经改善”或“文艺问题已解决”。普通夸张、玩笑、关心和相关提问都不按禁词处理。反例组前几轮也连续提问，之后没有维持每轮追问；仍值得后续用新场景观察。

阅读结论来自主代理逐轮核对，以及另一 agent 只看匿名甲乙标签的辅助审读。后者先提交观察、再核对标签映射；不是外部人类盲测，也不是统计显著性或自然度评分。

## 实际证据核验

36 个 evidence 均为 `completed`，每个请求逐条核对：

1. 两组人物资料逐字一致，反例组新增系统块与 v0.1 文件逐字一致，基础组不含该块。
2. 每轮实际传出的用户与助手历史，均等于对应已保存会话截至当前用户消息的完整前缀，没有提前裁剪、摘要或混入另一组历史。
3. 原请求、wire 和输出的 SHA-256 均匹配；system 转 developer 后，实际传输的文字与原文字段一致。
4. 原始输出与正式接口保存的助手正文逐字一致，没有为了更顺口而后处理、删词或截断。
5. 实验运行源码与启动时私有快照逐字/hash 一致，提示词整个过程中未改动。

已核实并停止本轮 live PID，进程正常退出，再启动不加载凭据的 `--review` 实例。实际登录只读实例的管理员 API，读取两组各 36 条非空消息（18 个用户消息、18 个助手回复）并对照完整记录一致；复查入口的 `canGenerate=false`，生成请求实际返回 403。既有旧实验的复查服务没有被停止或改写。

这些是实际请求、保存及只读接口核验，不是本轮重新完成后台视觉验收；本轮没有 UI 改动。

- 实验离线检查通过，新增验证相同历史下只差一个完整提示块、宿主 canary 排除、完整历史、wire 文字、原文 hash 及缺失/歧义路由拒绝；全部零模型调用。实际 36 次调用与这些离线检查分别记账。

- 独立 agent 的源码复核完成。OpenCode 指定模型审查返回 401 `api_key_expired`，没有有效正文，未切换模型或调整凭据，不能声称该外部审查通过。

当前可支持的结论是：这个样本中，反例组减少了连续生活安排，能更自然地收尾，且明确求助时仍能给出有效内容。还不能证明稳定有效；下一步重点是明确求安慰时的精修表达，以及在不复制现有测试话题的新情境中复测。本轮保留 v0.1 原样，不边测试边修改提示词。
