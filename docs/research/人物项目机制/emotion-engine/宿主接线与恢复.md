## 工具存在以后，还差什么

MCP/CLI 是读写情绪状态的入口，不是自己维持生活的 Agent。真实接入必须回答：谁开启会话，谁解释已察觉事件，谁调用写入，谁将摘要塞进下一次模型请求，谁关闭会话并结算信任。作者提供的最小 Agent 示例使用 mock 决策，能展示调用顺序，不能证明真人感。[^ee-map-entry]

| 编号／机制 | 何时触发、依据什么 | 保存变化 → 谁读取／行为边界 |
| --- | --- | --- |
| EE10 重复调用和有限去重 | session/event/evidence/settlement 标识检查 | 重放不应重复加分；已处理事件及结束会话有保留上限，**只保证保留窗口内精确防重**。活跃会话受另一套压缩约束。[^ee-map-retention] |
| EE11 长期运行的压缩 | 活跃轨迹/证据超上限，或显式 compact_log | 将旧轨迹/证据聚合成摘要用于后续模式和结算，压缩低价值日志。不是完整聊天记忆、无限审计或可从摘要还原全部原文。[^ee-map-retention] |
| EE12 给下轮模型的实际材料 | 宿主调用 summary / prompt_preview / 集成示例 | MCP 摘要包括近期关系意义、open_loop 和倾向；通用 preview 更窄，主要取情况及评价标签。保存过不等于所有适配器都会读取，最终回复由宿主模型生成。[^ee-map-consumer] |
| EE13 暂停、恢复、清空与重置 | 管理入口 pause/resume/clear_log/reset | 暂停保留状态，恢复选模式；普通 reset 保留身份/人物配置，factory reset 更彻底。清日志不等于清除所有轨迹和关系证据；是管理机制，不是人物主动静音收件箱。[^ee-map-admin] |
| EE14 审计、迁移与修复 | validate/audit/repair_plan；旧版本显式 migrate/upgrade | 检查账本一致性，迁移保留扩展；repair_plan 只是建议且不自动猜身份。reconcile_trust 需明确基线，默认预览、显式 apply 才写入，不是随意从聊天重建真相。[^ee-map-repair] |
| EE15 持久化与宿主接线 | CLI 或 stdio MCP 写入；客户侧 Skill/脚本触发生命周期 | 锁、原子替换、备份恢复保护状态；受管模式拒绝坏结构和缺失能力。工具可调用不等于每轮已调用，安装/注册脚本与真实生命周期接线要分开验证。[^ee-map-storage] |

## 读取路径决定实际效果

MCP 的 compact_memory 包含近期关系意义、open_loop 与后续倾向；通用 prompt_preview 对近期日志只取情况与评价标签。两个消费者不完全相同。即使写入了很好的事件解释，若宿主只用较窄的预览，模型未必看到它。接入核验必须看最终请求中的实际材料，不能只检查状态文件里“有这个字段”。[^ee-map-consumer]

```text
已察觉事件
  → 宿主解释并确认归属
  → evaluate / record_turn
  → 锁内校验、写状态与账本
  → summary 或具体宿主适配器选取材料
  → 下一轮模型请求
  → 模型选择行动 / 回复
```

这条路径没有把“安排待办、发送消息、发布内容”交给本引擎。它维护的是其中的情绪与关系材料。

## 重试和长期运行的限制

重复事件 ID、重复会话结算都有检查，但历史去重标识有保留上限，不是无限期精确防重。活跃会话轨迹、证据与日志也会压缩；汇总保留意义不等于还原所有原文。需要长期可审计的事实历史，应有宿主的权威记录，不能把本包当全量事件库。[^ee-map-retention]

锁、原子替换和备份恢复解决文件层问题。受管模式对坏 schema、身份和能力缺失拒绝写入；repair_plan 只提出修复建议，不猜未知身份。reconcile_trust 要求明确基线，默认返回预览；显式 apply=true 可直接写入，源码不强制先预览，不能无依据倒推一段真实关系。[^ee-map-storage][^ee-map-repair]

pause 保留状态而停更新，clear_log 只清相关日志，不代表全部历史与证据已消失；它们是管理控制，不是人物决定不看手机。reset/factory reset 的范围不同，业务必须明确要重置什么。[^ee-map-admin]

## 覆盖、运行证据与未验证项

本轮核查主工具分派和状态读写，没有运行真实模型或长时服务。2026-10-22 的指定离线测试与重复衰减探针保留在[专项研究](../../人物主体、日程调整与情绪状态的进一步研究.md#emotion-engine实测的工程价值与两个适配问题)。没有以这些单元测试证明用户最终聊天感受，也没有宣称候选已被采用。

以后若试接，优先核对：一件事只算一次、同一时间段只衰减一次、私聊只影响获准的材料、摘要实际进入请求、错误后可恢复、管理清空范围可说明。它们是拟议验证条件，不是本轮新增实现。
