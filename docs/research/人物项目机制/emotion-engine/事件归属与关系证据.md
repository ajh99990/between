## 先判断“这是什么变化”，再决定写哪里

“我把报表交了”是任务进展；“我不喜欢每次都被催”可能是稳定偏好，也可能是一场关系事件；她自己睡不好是自身状态。这些材料不能都写进“她对用户的感情”。引擎要求宿主提交 subject、event_type、host_approved 和可选 memory_owner，用无副作用的策略函数提出路由。批准字段表示宿主已验证这个判断，不要求每轮向真人弹确认。[^ee-map-policy]

| 示例输入（自拟） | 关键字段 | 策略结果及真正边界 |
| --- | --- | --- |
| 完成报表 | subject=task，memory_owner 已提供 | route_host_memory；还没有写入宿主的任务记忆 |
| 今天独自疲惫 | subject=self，host_approved=true | state_only；更新情绪与轨迹，通常不写同类关系情绪日志 |
| 被甲逼迫、关系受伤 | subject=relationship，event_type=boundary，host_approved=true | record_emotion；允许保存状态与事件解释 |
| 泛泛夸奖 | 没有明确关系事件 | respond_only；不让每句“真棒”都自动涨信任 |

这是源码策略的例示，不是替人物决定回复、沉默或原谅。默认 light；即使改成 always，显式所有权/批准限制仍然存在。[^ee-map-policy]

| 编号／机制 | 何时触发、依据什么 | 保存变化 → 谁读取／行为边界 |
| --- | --- | --- |
| EE04 这件事归谁记 | `record_policy` 用事件主体、类型、批准标记及辅助关键词分类 | 返回 respond_only、route_host_memory、state_only、record_emotion。任务进展/稳定偏好指向宿主记忆；**返回路由建议不等于已经替宿主保存**。默认 light，暂停不更新；always 也不取消所有权和批准条件。[^ee-map-policy] |
| EE08 情绪日志和未完事项 | record_turn / log_event 接受情况、人物视角、关系意义、影响、open_loop、后续倾向 | 写紧凑日志，供宿主读取。“还想问清楚”是提示材料；本仓库没有因此自动建立到期任务或执行工具。self 的 state_only 路径仍有状态/轨迹，只是不写同样的情绪日志，不能解释为完全无痕。[^ee-map-record] |
| EE09 显式证据改变信任 | 互动提交 trust_evidence；关闭会话后调用 settle_trust | 只消费可用证据，按规则结算、标记已消费。道歉标签、心情变好不直接加信任；独立 update_trust 要批准与原因。例外入口不是不存在，需统一宿主调用约束。[^ee-map-trust] |

## 为什么存事件解释

情绪日志除了数值，还可以保存 situation、角色视角、关系意义、impact、open_loop、follow_up_bias 和 salience。下一轮看到“有点不快”远不如看到“她觉得答应好的边界再次被忽略”容易接续。

但 open_loop 只是内容字段。例如“还想问他是否记得约定”并不自动产生 15:00 的提醒。引擎没有日程执行器；需要行动的事项由宿主另建，不能把一条日志当作履约系统。[^ee-map-record][^ee-map-consumer]

## 信任是另一本账

当前情绪改善不直接意味着长期信任上升。提交关系证据后，结束会话、调用 settle_trust，程序检查：身份是否一致、会话是否已关闭、有没有其他活跃会话、是否已结算/重复事件、有无尚未消费证据。通过后计算变化、标记证据被消费、保存结算记录。[^ee-map-trust]

```text
# 对源码结算顺序的简化
settle(session_id, event_id):
    require_expected_identity()
    if not enabled: return paused
    if session_not_closed: return session_not_closed
    if other_session_active: return active_session_conflict
    if already_settled or duplicate_event: return unchanged
    evidence = eligible_unconsumed_evidence(session_id)
    if not evidence: return no_eligible_evidence
    delta = assess(evidence)
    apply_bounded_trust_change(delta)
    mark_evidence_consumed()
    record_settlement_and_event_id()
```

这里 `paused` 是返回状态名；结算入口检查 `enabled=false`，并不检查 `runtime_mode=paused`。后者属于 `record_policy` 的判断，不能将两个暂停条件混为一谈。[^ee-map-trust]

甲说“刚才是我急了”，宿主可能把她当前感受调缓，却不必提交高质量修复证据；后来甲实际尊重了约定，才可能有更强证据。是否算证据、怎么评价仍依赖宿主；程序只保证所配置的结算规则被执行，不能保证人物心理判断正确。另有需批准与理由的人工 trust 更新入口，因此接入时也要约束管理通道，而不是声称所有信任改变只能来自自动结算。[^ee-map-trust]

## 对我们仍然开放的问题

逐关系情绪有明确对象，适合表示“和甲相处时仍别扭”；全局疲惫又可能来自她自己的生活。我们保留共享、逐关系、条件外溢三条路线。严重私下冲突影响之后的心情，不等于允许把甲的身份与私聊原文提供给乙；感受传播与信息可见范围应分别研究。本引擎没有替我们完成这层组织。正式决定统一见[现行方案决定](../../../plans/人物主体Agent方案/02-决策依据与取舍.md)。
