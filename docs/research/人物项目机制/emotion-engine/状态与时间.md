## 从最基本的概念理解

想象她刚被催得不舒服：这次触动可能很快过去，今天的疲惫仍会延续，她长期是否信任对方又是另一回事。这个引擎把三者存成不同字段，让它们有不同的变化速度；它不声称这些数字就是人的真实情感。

PAD 是愉快程度（P）、激活程度（A）与掌控感（D）的数值表示。当前状态和人物基线都使用它；pulse 是最近变化引起的短时波动，trust 是另行结算的关系值。输入的语义解释仍来自宿主或模型。[^ee-map-identity][^ee-map-time]

## 一份包的关键字段

下面仅为实际默认结构的节选与示例身份，省略历史数组；不是一个完整、可直接提交的 API 请求。

```json
{
  "identity": {"state_id": "state-1", "character_id": "person-1", "relationship_id": "contact-a", "status": "bound"},
  "enabled": true,
  "runtime_mode": "light",
  "volatility_profile": "steady",
  "emotion": {"pleasure": 0.0, "arousal": 0.3, "dominance": 0.5},
  "personality_baseline": {"pleasure": 0.0, "arousal": 0.3, "dominance": 0.5},
  "trust": 0.1,
  "trust_anchor": 0.1,
  "last_interaction_iso": null,
  "session": {"active_session_id": null, "status": "closed"}
}
```

完整状态还包括 affective_pulse、emotion_trajectory、emotion_log、trust_evidence、trust_settlements、session_ledger、processed_event_ids 等。P 范围 −1～1，A、D 为 0～1。一个包绑定一个关系，当前设计没有自动把多个包的心情合成为一个人的整体心境。[^ee-map-identity]

| 编号／机制 | 何时触发、依据什么 | 保存变化 → 谁读取／行为边界 |
| --- | --- | --- |
| EE01 身份绑定与状态所有权 | 初始化绑定 `character_id + relationship_id`；受管写入核对请求身份、schema 和 capabilities | 防止把甲的状态写到乙。一个包同时包含 PAD 与 trust；是否保留这种逐关系情绪，是我方待比较方向，不是源码缺陷的直接结论。[^ee-map-identity] |
| EE02 人物基线与波动档位 | 显式 `configure` 读风格描述；`tune` 读调整要求 | configure 根据描述关键词与推导特征生成基线并选择 steady/expressive 等波动档位；tune 根据关键词调整基线和解释。后续衰减和 pulse 读取这些配置。不是模型从人生经历学习人格；配置也会把当前情绪向新基线混合，不能当无副作用描述编辑。[^ee-map-profile] |
| EE03 会话开始、结束和冲突 | 宿主明确调用 session_start/end；携带 session_id/event_id | 新会话按时间更新状态并建账；同一包已有另一活跃会话则拒绝开启，不能无条件并行写。结束冻结本会话供结算，不是等网页关闭便自动成立。[^ee-map-session] |
| EE05 语义判断与数值写入 | 宿主提供最终 PAD，或接受辅助建议；evaluate_turn 联合归属检查 | record_turn 保存最终值、轨迹、最近互动时间并据差值生成 pulse。关键词 appraisal 是辅助，不是完整语境理解；host_approved 是宿主协议字段，不是必须每轮弹人工确认。[^ee-map-record] |
| EE06 短暂情绪波动 | 一次被接受的状态变化产生 affective_pulse | pulse 与心境分开，在 pre-turn 按档位快速回落；下一次摘要呈现短时触动。不是另一套自动行为裁判。[^ee-map-time] |
| EE07 跨时间与逐轮恢复 | 新会话/显式 decay 按真实间隔；pre-turn 按轮回拉 | 当前心境趋向人物基线，长期信任另有时间规则。两种时钟不能混称“每分钟恢复”；独立 decay 重复计算同一时间段的问题见专项补查的实际探针。[^ee-map-time] |

## 写入的不是“生气值增加 0.2”

正常 record_turn 接收的是宿主已判断的**最终 PAD**。程序记录这个最终值，再由新旧差值派生 pulse，并保存轨迹和时间。没有提供值时，evaluate 路径可使用关键词辅助建议；这种建议不能等同于理解了一段复杂中文关系。[^ee-map-record][^ee-map-policy]

```text
# 解释性伪代码，不是完整调用签名
start_session(identity, session_id, event_id)
context = pre_turn_update(state)       # 逐轮回落及短波动衰减
judgment = host_interpret(context, noticed_event)
route = record_policy(judgment)
if route == record_emotion or state_only:
    state.emotion = judgment.final_PAD # 最终值，不是再次加 delta
    state.pulse = change(old_PAD, final_PAD)
    append_trajectory(event_id, judgment)
    persist_under_lock(state)
```

例如，示意当前 P=0.1、A=0.3，宿主认为催促令她不快而紧绷，提供 P=−0.2、A=0.6。引擎保存这些值，之后逐轮/跨时间恢复与短波动各走规则。这些示例值是解释材料，未证明该幅度符合真人。

## 有两种不同的时间推进

新会话和显式 decay 使用实际时间间隔；pre-turn 使用轮次规则。它不是一条一直运行的后台定时器。若我们希望角色无人联系时仍演化，宿主需要安排调用，并保证同一段时间不重复结算。此前探针已经发现独立 decay 入口重复计算同一时间段的风险；探针及数值在[专项研究](../../人物主体、日程调整与情绪状态的进一步研究.md#emotion-engine实测的工程价值与两个适配问题)，不能把它写成所有入口都已修复。[^ee-map-time]

配置人物基线也会把当前情绪向新基线混合，tune 由关键词调整基线与解释，波动档位由 configure 根据描述关键词与推导特征选择。它是可解释的配置机制，不是从整个人生自动学出性格。模型如何评价当前经历，数值怎样延续，行为如何选择，仍是三个不同问题。[^ee-map-profile]
