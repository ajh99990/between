## 提取到保存的一整笔事务意图

### 选择基线与模型请求

触发后先验证：扩展开启、自动或手动入口合规、有合格消息、没有另一提取正在跑；普通事件发现 tracker 已存在即跳过，明确 Retrack/编辑/新 swipe 则强制重算。随后选定 `lastIndex`，把当前目标排除在基线之前，只用目标以前的聊天与状态。这样同一条回复点 Retrack 不应在刚算出的增量上再加一次。[^src-1] [^src-2]

模型请求包含本次 owner、最近消息（默认10条）、前值、最多取到的近期相关状态记录（代码先取6条再按索引和owner过滤）、可选角色卡/激活 lorebook。owner 已出场却在最新一份快照缺值时，还会从合并历史补连续性。用户scope与角色scope分开取前值；最新global custom单独覆盖。[^src-3] [^src-4]

模型不负责保存。它负责解释语义并提议 JSON；程序负责识别 owner、字段类型、缺失回填、范围与可信度。旧 `legacy` 名字也不等于自由散文：其提取协议同样要求 JSON。新 `json` 模式另走版本化请求/响应与adapter，失败不静默切回旧模式。[^src-5] [^src-6] [^src-7]

### 统一、逐项与私有批次

默认 unified 把所有启用公开 built-in+custom 合到一个批次；如果有私有字段，再为每个 owner 分别请求私有批次。逐项模式把 built-in分开，custom可按配置 group合批，并受 worker并发数约束。**sequential 的产品名不意味着所有 HTTP 请求必然串行**，实现有 worker queue。[^src-8] [^src-9]

字段不全/格式不符时有有限 JSONrepair；统一批次会判断所请求各类别有没有覆盖。输出缺项最终可保留此前值，不能把所有未更新都解释成“模型认为没变化”。这正是 raw → parsed → applied 诊断分层的价值。[^src-10] [^src-11]

### 保存与失败不是魔法原子操作

成功后构造 TrackerData，写 `context.chat[index].extra.bettersimtracker[String(swipe_id)]`，同步 entityRegistry，调用宿主 saveChat，刷新 prompt与UI。副本保存于首消息 extra 的 `bettersimtracker:chat`、chatMetadata、本地localStorage历史/latestByScope。它依赖宿主保存，不是独立后台数据库。[^src-12] [^src-13] [^src-14] [^src-15]

手动停止 abort 请求和调度，尚无原tracker时给“未保存”的恢复入口；已有tracker时保留原快照。不应把输入数据还留着与模型真的完成提取混淆。若 saveChat 本身失败，内存写入发生在它之前，而且 persistence 会再尝试 debounced 保存后抛错；不能声称“任意异常都无部分更新”。[^src-16] [^src-17] [^src-18]


## 用户状态先提取门闩

它解决的是“用户这一句改变了自己的姿态/服装/心情，但角色回复已经开始生成，来不及读新状态”的顺序问题。

默认 User Tracking 关闭。开启后，USER_MESSAGE_RENDERED 记录这条用户消息的索引与原文，先提取用户 Mood/Thought/custom。若宿主已开始角色生成，拦住并保留生成意图；提取成功再校验“仍是同一条最新用户消息、文本没被改、后面尚无 AI 回复”，重放先前的 generate(type, options, dryRun)。群聊重放还会归一化目标角色/自动触发参数。[^src-19] [^src-20] [^src-21] [^src-22]

这条门闩不是“她决定半小时不看消息”，没有角色的社会可打扰性判断；也不是“已读但承诺15点补回”。它属于短期生成流程协调。若将来采用该代码，应保持这三个概念分离。


## 状态如何真的影响后续表现

注入器是清楚的读取者。它过滤禁用字段、includeInInjection、User Tracking注入开关、目标owner私有字段，构建SYSTEM扩展提示：状态语义、数值区间、行为倾向、人格和情境优先规则、owner值、可选summary note。它不是把状态数字直接展示成角色说话内容；提示要求隐式影响措辞/情感可用度，禁止在可见回复中提tracker数字。[^src-23] [^src-24]

默认开注入，但用户可只用它当显示账本。超6000字符时逐步削custom条目与解释，最后最简截断；所以“跟踪了一个字段”不等于“聊天模型必然收到它”。保存前后的injection快照用于诊断，能分清刚才那次生成实际用了什么与现在准备下次用什么。[^src-25] [^src-26] [^src-27]

宏提供另一种明确消费路径：`bst_injection`、`bst_stat_user_*`、`bst_stat_scene_*`、`bst_stat_char_*_<target>`、image state。私有字段和场景归属有各自过滤；角色无后缀宏只在无歧义目标下暴露。宏输出被外部模板采用之后才会有效，存在宏不等于某个图像工具已经自动接好了。[^src-28]

摘要是第三种路径：用户点击Summarize，把状态变成叙述Note插入聊天；默认不让AI看，另有“注入摘要”开关。UI图表是第四种读者，平滑只改图线。这些机制不能混为“记忆模块”。[^src-29] [^src-30] [^src-31]
