# 数据结构与读写路径速查

固定上游 `ghostd93/BetterSimTracker@5b818855c0f8a4f93a9633eaff4f1287ac26ab9c`。以下值均为说明用假设，字段与存储层级按源码核对；未运行模型。[返回总索引](README.md)。

## A. 模型输出不是最终持久化结构

默认 legacy/unified提取协议的简化响应：

```json
{
  "characters": [{
    "name": "小林",
    "confidence": 0.8,
    "delta": {"affection": -4, "trust": -12, "desire": 0, "connection": -2},
    "mood": "Angry",
    "lastThought": "我现在真没空一直回。"
  }]
}
```

模型交的是“这轮应该怎么改”，`parseUnifiedDeltaResponse`解析，`applyParsedForBuiltInOrTextStat`调用限幅/可信度函数后才得到绝对值，`mergeStatisticsWithFallback`补齐未提取字段，最终`buildPersistedTrackerSnapshot`产出保存对象。因此诊断里raw、parsed、applied应分开看。[^src-1] [^src-2] [^src-3]

## B. 消息实际保存层级

特别注意：`bettersimtracker`下面直接是swipe键映射，**没有名为swipes的额外包装字段**。下例只列当前分支0；若换成另一候选，可以并存"1"。

```json
{
  "mes": "我这边还没弄完，先别一直催。",
  "name": "小林",
  "is_user": false,
  "swipe_id": 0,
  "extra": {
    "bettersimtracker": {
      "0": {
        "timestamp": 1792735800000,
        "activeCharacters": ["小林"],
        "statistics": {
          "affection": {"小林": 62},
          "trust": {"小林": 50},
          "desire": {"小林": 5},
          "connection": {"小林": 56},
          "mood": {"小林": "Angry"},
          "lastThought": {"小林": "我现在真没空一直回。"}
        },
        "customStatistics": {"fatigue": {"小林": 65}},
        "customNonNumericStatistics": {
          "location": {"__bst_global__": "办公室"},
          "holding": {"小林": []}
        }
      }
    }
  }
}
```

这是简化形态；dynamic模式还可能有`statisticsByEntityId`、custom对应影子桶、`entityResolution`、`entityOwnerMap`；人工清除可以带`clearedStatistics`等。`holding:[]`是明确空，不等于字段缺失。默认schema没有location/fatigue/holding，必须显式添加这些custom定义。[^src-4] [^src-5] [^src-6]

写者：正常提取、bootstrap、人工编辑；读者：`getTrackerDataFromMessage`按当前swipe读取，再经runtimeState/history合并供UI/注入/宏使用。旧单TrackerData无分支格式仍可读；首次再次写入时放到"0"。[^src-7] [^src-8] [^src-9]

## C. 自定义定义、共享与私有的区别

```json
{
  "id": "fatigue",
  "kind": "numeric",
  "label": "疲劳",
  "description": "用于提取器的语义说明",
  "behaviorGuidance": "用于后续聊天模型的行为说明",
  "defaultValue": 40,
  "maxDeltaPerTurn": 8,
  "track": true,
  "trackCharacters": true,
  "trackUser": false,
  "globalScope": false,
  "privateToOwner": true,
  "showOnCard": true,
  "showInGraph": true,
  "includeInInjection": true
}
```

此例仍是可配置schema示意，非推荐人物提示词。description帮助模型判定字段；behaviorGuidance帮助后续聊天模型消费字段，两者用途不同。globalScope=true将该stat按`__bst_global__`一份保存，并强制privateToOwner=false；privateToOwner只适用于owner级字段。提取时私有请求分owner，注入时只给目标owner的私有值，但整个浏览器聊天仍能显示/导出相关状态，不能当安全ACL。[^src-10] [^src-11] [^src-12] [^src-13]

## D. 动态身份、场景与当前消息

```json
{
  "entityResolution": {
    "source": "model",
    "resolvedEntities": [{
      "entityId": "运行时生成的稳定ID",
      "kind": "narrative-entity",
      "name": "小林",
      "aliases": ["林姐"],
      "inScene": true,
      "inMessage": true,
      "created": false
    }, {
      "entityId": "另一个稳定ID",
      "kind": "narrative-entity",
      "name": "同事小周",
      "inScene": true,
      "inMessage": false,
      "created": false
    }]
  }
}
```

小周仍在场不代表本轮与用户的关系必须一起变化。用于长期回看身份的`entityOwnerMap`和`statisticsByEntityId`可避免重名/改别名把旧状态归错人；registry在`chatMetadata.bstEntityRegistry`，version1、entities、ownerToEntityId，entry有生命周期事件消息索引。[^src-14] [^src-15] [^src-16]

当前公开模式类型只有`standard|dynamic_characters`。内部函数仍叫multi-character；旧值`multi_character`和`dynamic_entities`在load时归一成dynamic_characters。不要把旧命名误写成当前UI上三个独立模式。[^src-17]

## E. 存储副本位置与权威边界

|位置|结构/用途|主要写者与读者|
|---|---|---|
|chat[index].extra.bettersimtracker[swipe]|本消息本候选的TrackerData|writeTrackerDataToMessage / getTrackerDataFromMessage|
|chat[0].extra["bettersimtracker:chat"]|latest+history|writeChatStateStore / readChatStateStore|
|chatMetadata.bettersimtracker|latest+history|writeMetadataStore / readMetadataStore|
|localStorage的history scope与latestByScope|受限恢复缓存|saveTrackerSnapshot / getLocalLatestTrackerData|
|chatMetadata.bstEntityRegistry|人物身份、别名与生命周期|registry sync / resolver、UI、宏、history|
|宿主extensionSettings.bettersimtracker + local fallback|全局定义与默认配置|saveSettings / loadSettings|

副本不等于多份独立真相：runtimeState优先安全消息快照，回退要匹配目标消息；latest快照排序优先消息索引，不以人工编辑时间戳把旧行提升到现在。写内存→宿主saveChat的顺序也不是原子事务。[^src-18] [^src-19] [^src-20] [^src-21] [^src-22]

## F. 需要定位时按这条函数链走

```text
init → registerEvents
  GENERATION_STARTED: snapshotInjectionForGeneration
  GENERATION_ENDED / late CHARACTER_MESSAGE_RENDERED:
    scheduleExtraction → runExtraction
      resolveActiveCharacterAnalysis / executeEntityResolverModelRequest
      getLatestCharacterOwnedTrackerDataWithIndexBefore
      buildRecentContext + seedHistoryForActiveCharacters
      extractStatisticsParallel
        buildUnifiedAllStatsPrompt → generateJson
        parseUnifiedDeltaResponse → applyConfidenceScaledDelta/resolveMoodWithConfidence
      mergeStatisticsWithFallback → buildPersistedTrackerSnapshot
      writeTrackerDataToMessage → saveTrackerSnapshot
      syncEntityRegistryFromTrackerData → persistChatNow
      refreshPromptMacroData → queuePromptSync → syncPromptInjection
      queueRender → renderTrackerUI
```
