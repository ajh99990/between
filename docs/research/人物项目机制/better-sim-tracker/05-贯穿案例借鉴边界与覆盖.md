## 一个贯穿案例：打断、恼火、道歉与之后

以下为自拟数据，说明默认 unified+standard+character tracker 的确定代码运算，不宣称模型实测会给这些数。

**起点**：当前聊天角色小林，历史最新状态 affection65/trust60/desire5/connection58/moodNeutral。可选custom记录地点办公室、当前事务赶报表。这些环境值来自已有文本/人工定义；扩展不会自己执行“写报表”或推进真实日程。

**用户发消息**：“你怎么还没回，快点。” 默认角色生成仍先发生。它结合已有对话和上一份状态说：“我这边还没弄完，先别一直催。” 然后生成结束才启动提取。输入大致为：

```json
{
  "targetMessageIndex": 12,
  "owners": ["小林"],
  "previous": {"trust": 60, "affection": 65, "connection": 58, "desire": 5, "mood": "Neutral"},
  "recentMessages": ["用户催促", "小林刚才的实际回应"],
  "history": ["目标消息之前的相关快照"],
  "maxDeltaPerTurn": 15
}
```

**假设提取输出**：confidence=.8，trust delta=-12，affection=-4，connection=-2，desire=0，Mood=Angry，thought为一条当下念头。程序用scale=.35+.8×.65=.87，把trust变50、affection62、connection56、desire5；.8≥.6，接受Angry。保存到第12条当前swipe，并让下一轮注入读到新状态。

**随后道歉**：“行，我刚才有点急，你先忙。” 本轮聊天模型已经可见前面的Angry与关系下降。假设它回复“嗯，晚点说”，提取模型建议moodNeutral、trust+2、affection+1、connection0，confidence=.75。程序将trust由50变52，而不是因为情绪转回Neutral就把trust自动恢复60。这只是因为它们是不同字段，各自提议/保存；该项目没有另一套独立证据法庭判定信任是否真的应增长。

**十分钟没人说话**：上述已查链路没有按真实时间自动恢复心境的动作；保存值保持。若下一段文本说“她休息后心情好了”，再次提取可能改变mood。自定义date_time也要有提取/人工输入驱动，不能据其存在推断日常生活自行推进。

**用户重生成刚才那句回复**：新swipe单独算新快照，旧swipe保留；切回旧版就读旧状态。**手动把trust改成55**：编辑器直接保存55并刷新。**编辑更早的催促文字**：默认重提取那个目标行，但不保证后面“道歉”行自动全部重算。整条链的责任因此可检查，而不是一个抽象“情绪值控制回复”。

## 对我们研究的借鉴与保留问题（不是采用决定）

可直接借鉴的机制包括：提取建议与应用结果分层；目标消息之前的baseline；消息/候选分支归属；人工清除墓碑；按实体ID防重名；scene和message参与者分开；raw/parsed/applied/injected prompt诊断；显示、跟踪和注入开关分开。

不能现成等同于我们的部分：一个持续生活人物跨微信/B站/小红书的共享状态；多人各自的长期关系；日程历史保护；未读收件箱与注意关闭；读后待办和承诺补回；自主行动调度；真实世界事件结果与虚构叙事的区别。已核对的事件入口与数据字段未证实这些能力，不是对所有可能插件联动下绝对不存在的断言。

**情绪归属保持开放**：这个项目的owner mood可以启发“逐交互对象的表达状态”，global custom可以表达聊天场景共享变量，但均不足以证明全局情绪、逐关系情绪、条件外溢哪一种是我们唯一正确的选择。应分别比较：别人惹她生气后是否带入当前聊天、关系破裂是否只作用于某人、疲劳是否跨人共享、恢复速度和不公迁怒如何处理。本文没有把其中一种升格为决策。

还要警惕：默认行为guidance可能诱导过多关心；confidence来自同一个模型；关系技术初值50和固定delta限幅未经我们的体验验证；英文活跃启发式未验证中文；新旧JSON路径、历史重编辑以及多存储副本都带有测试成本。它提供的是有真实接线和恢复机制的插件候选，不是经过科学证实的拟人情绪真值系统。

- 写者：model extraction、manual edit、defaults/bootstrap、registry管理、settingsimport；读者：UI/cards/graph、runtime merged state、prompt injection、macros、summary、diagnostics；storage的write/read/migration兼容和scope也核查。
- 测试源码：swipe、空array、按消息序号而非写入时间合并、旧消息重提取、entity归属、手工改值、用户门闩安全条件、bootstrap去重与有限重试均有具体测试用例。只确认测试所表达的约束，没有运行这些测试，更不能据此声称角色体验合格。[^src-8] [^src-9] [^src-10] [^src-11] [^src-12] [^src-13]

- 作者在固定提交README首行明确声明没有时间继续维护；这是作者停止维护的直接证据。不要误写成“GitHub 已 archive”或“项目无可用价值”，两者都不是该句能证明的。[^src-14]
