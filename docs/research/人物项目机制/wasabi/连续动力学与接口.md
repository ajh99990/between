## 它接收的是已解释的冲击

如果有人催她工作，这个引擎不判断催促是玩笑、关心还是冒犯。宿主先作解释，选定一个模拟对象，再给一个正负冲击。后续引擎按物理式动力学持续更新；宿主读取 PAD 或各情绪激活，再决定如何用于表达和动作。[^api]

| 编号 | 机制 | 输入 → 状态 → 消费者 |
| --- | --- | --- |
| W01 | 模拟对象管理 | local/global ID 创建、查找、移除多个独立对象；不是现成的“一个人对多联系人”模型 |
| W02 | 冲击及参数 | emotionalImpulse 接收宿主解释的正负刺激；校验输入、限幅内部位置；质量、力、更新率等调整动力学 |
| W03 | 持续变化 | update 用时间步推进快情绪、慢心境及无刺激时的变化；宿主必须持续调用 |
| W04 | 表示映射 | 内部动力学位置转换为 PAD，再对应配置情绪区域的激活；Primary/Secondary 定义参与表示 |
| W05 | 输出和管理 | 获取 PAD/激活字符串、状态 transferable 读写、缓存和 reset；没有自动生成回复或执行日程 |

W01/W02 见引擎接口；W03 见 EmotionDynamics；W04/W05 见对象输出、EmotionContainer 及情绪定义。[^api][^dyn][^output]

## 具体运行顺序

```text
engine.add_attendee(person)
host interprets noticed event
engine.emotionalImpulse(person, signed_impact)
repeat on host simulation clock:
    engine.update()
    pad = engine.get_current_PAD(person)
    host uses pad + actual situation + relationship in its decision
```

这是解释性伪代码。实际 emotionalImpulse 限制输入在 −200～200，并将内部 X 限幅在 −100～100、重置相应力。动力学推进里情绪位置影响心境，弹性回落和无聊变化可以在没有新消息时继续；具体时间步来自更新率。不能将 signed_impact 直接称为一个通用“被冒犯程度”，其语义是宿主赋予的。[^api][^dyn]

## 能借什么，不能据此推断什么

它适合研究“没有新刺激时状态仍连续变化”，但没有事件语义评价、每段关系的信任证据或延后任务系统。多个模拟对象也未自动定义联系人状态怎样外溢成一个人的心境。PAD 映射和激活名称不是中文社会理解证据。

与 FAtiMA 相比，它更聚焦刺激后的动力学；与 Emotion Engine 相比，它不提供同样的关系证据与宿主生命周期协议。本轮没有编译或运行，不声称这套动力学改善了真人感。它保留为机制候选，不作为已采用方案。
