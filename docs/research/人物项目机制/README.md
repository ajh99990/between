## 推荐阅读顺序

先读各项目索引中的“为什么这样做”和贯穿一天的案例，再按感兴趣的机制进入分篇；最后读[横向比较与研究建议](横向机制与研究建议.md)。这样不会先把我们自己的框架套到上游，也不会仅凭一个类名选择整个项目。

每篇保留固定 SHA 的源码行号或测试出处，必要时有实际数据形状与伪代码。分篇中的同一假设例子是解释工具，不是运行记录。以后只在新问题、证据缺口或版本变化时补查，已查过的机制优先从这里定位。

平台真实动作与职业内容补查见[平台工具与内容生活补查](平台工具与内容生活补查.md)：固定工具版本、读取覆盖、发布结果、缺失能力和从业资料访问边界。
