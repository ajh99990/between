研究对象：`Yuralume/yuralume-core@6996b152604e83a1cf6344cd236a9b9456f47bba`。本篇从固定源码核对真实写入者、读取者和默认装配；未启动完整服务或调用模型。伪代码为解释真实分支的简化版本，示例为自拟，不代表效果测试。人物的 `user_id/operator_id` 主要指拥有它的账号，不能先解释成任意联系人。

## 各种“状态”的时间尺度和权威不同

| 材料 | 主要写入者 | 读取与作用 | 不能据此声称 |
|---|---|---|---|
| 平面 `CharacterState` | 默认SimpleStateEngine、恢复器、部分模型结果及回复保存 | 当前数值、意图等提示和门槛 | 所有情绪均来自成熟心理学模型 |
| `EmotionEvent` | 明确情绪事件提取，或旧state_suggestion兼容镜像；部分恢复事件 | 读时衰减聚合，prompt原因证据，长期反思 | 已实现任意联系人独立情绪与跨关系外溢 |
| `BodyState` | 创建/编辑/导入 | 非low症状入prompt | 饥饿/吃饭/睡眠已自动随时间模拟 |
| `SelfReflection` | 梦流程尾部的7/30天复盘 | 聊天读取叙述、主题与证据 | 只是再记一份对话摘要 |
| `Disposition` | 长期证据下的模型提案，程序按冷却小步更新 | 人物提示转成定性表达偏好 | 每轮心情直接改性格 |
| 习惯/称呼/关系起点 | 观察器、明确设定、关系一致性修复 | 日程与聊天/相遇 | 互动量能任意覆盖明确关系事实 |

相关结构和消费者见[^y-simple][^y-emotion][^y-body][^y-reflection][^y-drift][^y-patterns][^y-coherence]。

`SelfReflection`实际保存`character_id/operator_id/period/narrative/dominant_themes/period_start/period_end/evidence_quotes/created_at`，说明它有时间窗、证据和叙述，而非一个简单mood值。[^y-reflection-shape]

## 情绪事件的计算思路

模型负责判断这件事意味着什么、产生何种变化并留下证据；程序负责如何随时间保留这些影响。不是程序从“烦躁”这个词科学算出人的内心。

```text
读时投影(baseState, events, now):
  对每条未过期事件：
    weight = 2 ** (-(now-created_at) / half_life)
    若weight太小则忽略
    若applied_to_state为false：将delta * weight加到数值基线
    将valence/arousal按intensity与weight聚合
  单独选最近turn事件的情绪标签
  返回新状态；prompt另选衰减强度最高的若干事件原因
```

这样“她为什么心情不好”有了可回查来源，事件不会永远同样强烈。但本版本混有平面更新和事件投影，下节详述重复计入风险，不能把结构存在直接升级为系统成熟。[^y-emotion][^y-emotion-read][^y-emotion-writeback]

### Y13 情绪：本轮最重要的补查发现

此前把Yuralume写成“平面情绪+好感/疲劳/信任/精力四个值”明显不足。该版本已实现事件层：

```text
EmotionEvent {
 character_id, operator_id,
 cause_ref_kind, cause_ref_id,
 valence, arousal, intensity,
 affection_delta, fatigue_delta, trust_delta, energy_delta,
 emotion_label, evidence_quote,
 decay_half_life_minutes, expires_at,
 applied_to_state, created_at
}
```

普通回合后的模型可直接返回`emotion_events`，这条优先；没返回才从`state_suggestion`镜像出事件。新事件的数值变化`applied_to_state=False`，正常设计是在读取时用`2 ** (-elapsed/half_life)`折算，再加到平面基线；历史已经改过平面值的事件用True防止重复加。当前意图仍可直接保存平面字段。聚合产生正负感受、唤起度、强度排序和新的四项值；情绪名称取最近的turn事件标签，并非OCC类别推导。[^y-emotion][^y-emotion-write]

**谁真在用？** ChatService默认实例化该聚合器，按owner读取近24小时最多30条事件，投影到本轮状态供模型使用；提示另外按衰减后的强度挑前5个事件，展示时间、原因、标签、证据短句；人物状态接口也读投影，但该入口固定查询 DEFAULT_OPERATOR_ID，与聊天的 owner 查询不一致。可选 material digest 还会压缩这些材料，所以不能说所有配置下都把5条事件原样交给回复模型。[^y-material-emotion]长窗口反思和性格漂移还读取情绪事件。不只是后台可观测字段。[^y-emotion-read][^y-emotion-prompt]

但这个系统还不能直接称成熟可搬：

1. 主聊天路径默认仍装配`SimpleStateEngine`，按消息长度增加疲劳，匹配 `謝謝 / 喜欢 / 喜歡 / 開心` 时加好感，每条消息信任+1，匹配 `累 / 難過` 转 caring；回复含“陪/收到”转warm。和README的禁关键词宣言不一致。[^y-simple]
2. 读取时投影后的`pending_state`在回复完成时又写回平面CharacterState，原事件仍False；**单函数探针**证明若把投影结果再次当基线，同一事件会重复加。完整聊天链路尚未执行，但静态接线确实有这一风险，见本篇[投影探针](#可复查的情绪投影探针)。[^y-emotion-writeback]
3. 情绪读取是24h窗口，不等于配置了一个数周半衰期就一定会持续数周影响该聊天投影；反思的窗口另算。
4. `operator_id`是owner账号语义，并不是已经实现一个共享人物的任意联系人情绪分区。人物状态接口固定用 DEFAULT_OPERATOR_ID 查询，休息恢复事件也以 DEFAULT_OPERATOR_ID 保存；聊天则按 owner 查询。非 default 所有者下可能出现界面投影与聊天材料不一致，需整合验证，不能称为已证实的跨联系人泄露。[^y-api-emotion]
5. 最新turn标签的选择不等于“当前最强烈情绪”：标签从原始事件列表选择，未像数值和 top_events 那样过滤过期/低权重事件；不应据此声称有成熟的跨关系情绪外溢。

正确候选定位是：**它提供了值得借鉴的“有原因的情绪事件+时间投影+prompt消费者”整体链路，但仍有兼容层混合与作用域问题。** 这应重新进入我们的情绪系统比较，不应因前轮概括不足就只比较EE/FAtiMA。

### Y14 身体、时间与恢复分开看

休息恢复在聊天加载与后台tick都会运行，按距上次活跃时间将疲劳衰减、精力趋向满值；久未联系还有模型判断idle drift写当前状态/事件，让时间间隔不只是一行时间戳。前者是代码公式，后者是模型语义。[^y-recovery]

另有需要后续验证的静态风险：恢复器保存已衰减数值，却保留旧 last_active_at；再次刷新可能对新基线重复应用同一段闲置时间。按当前公式固定4小时，疲劳64两次会算成32再16；这是公式推导，**不是本轮服务或探针输出**。列表读取和后台 tick 都可能触发恢复，因此恢复快慢可能受刷新次数影响。[^y-rest-repeat]

`BodyState`保存饥饿、口渴、睡眠债、季节过敏的low/medium/high，非low渲染给模型。**本次全仓读写搜索只确认角色创建/编辑/导入及提示读取，没有发现时钟推进饥饿、吃饭消除饥饿的自动生活更新器。** 所以只能说有身体状态输入接口，不能说有生理模拟。[^y-body]

### Y15 反思、缓慢人格变化和回忆录

persona梦流程尾段依次调用关系里程碑、自我反思、性格漂移、行为习惯、称呼观察和关系一致性修复。反思读取7/30天窗口的高重要记忆、情绪与persona 片段，保存SelfReflection，再由聊天prompt读取。反思和漂移读取的情绪摘要使用最多80条原始事件的 valence 均值和原始 intensity 峰值，并不是直接复用聊天的指数衰减快照。[^y-reflection-aggregation]性格漂移读取长期证据，由模型提出改变哪一维、方向与证据，程序只移动一档，同一维默认30天冷却，再保存Character.disposition与历史记录。回忆录是面向用户整理展示已有记忆/反思的表面，不是又凭空编一份人生。[^y-dream-tail][^y-reflection][^y-drift]

一项重要依赖：这些机制挂在梦流程后面，若 persona 未装配或梦的候选数/安静时段/冷却门槛一直不达标，就不能保证每周/月自动反思；反思与漂移各自还要求足够的符合条件记忆。7/30天是回看窗口，不是保证每7/30天执行一次。这是当前主线尚未完全独立化的地方。

### Y16 习惯、称呼与关系校准

梦中观察器统计近期日程重复模式，再用模型提取语言习惯；日程规划器读recurring patterns，聊天读phrase habits，形成“过去常这样做”对下一次的影响。称呼偏好与显式关系/改名记录分开保存；一致性修复读原始对话与权威关系起点，修复把A称呼B倒置等污染。关系里程碑根据互动量档位跨越写高显著记忆，但说明不能因此覆盖初始关系。[^y-patterns][^y-coherence][^y-milestone]

它带来连续性，也可能反复强化模型自己生成的口头禅；自然度必须另测，不能把“能观察到习惯”当成“习惯优秀”。


## 可复查的情绪投影探针

环境：Python 3.14.6。源代码固定上述SHA，无数据库、无网络模型调用。工作目录为归档根目录，执行：

```bash
PYTHONPATH=src python3 - <<'PY'
from datetime import datetime, timezone
from kokoro_link.application.services.emotion_aggregator import ExponentialDecayEmotionAggregator
from kokoro_link.application.services.emotion_state_projection import project_state_from_emotion_events
from kokoro_link.domain.entities.emotion_event import EmotionEvent
from kokoro_link.domain.value_objects.character_state import CharacterState
now=datetime.now(timezone.utc)
s=CharacterState(emotion='neutral',affection=50,trust=50,fatigue=10,energy=80)
e=EmotionEvent.new(character_id='c',operator_id='u',cause_ref_kind='turn',affection_delta=10,now=now)
a=ExponentialDecayEmotionAggregator()
p1=project_state_from_emotion_events(state=s,events=[e],aggregator=a,now=now)
p2=project_state_from_emotion_events(state=p1,events=[e],aggregator=a,now=now)
print('pure projection baseline affection:',s.affection,'first read:',p1.affection,'projected state reused as baseline:',p2.affection,'event applied_to_state:',e.applied_to_state)
PY
```

实际输出：

```text
pure projection baseline affection: 50 first read: 60 projected state reused as baseline: 70 event applied_to_state: False
```

边界：这是**单函数连续投影实测+接线静态推断，未完整运行聊天服务**。静态链是`chat_service.py:2252–2268`投影pending_state→`2423–2429`转final_state→`2457`保存人物；stream同样`3048–3052`→`9286–9303`。此结果不代表情绪事件设计没有价值，它说明“只读投影不能回写成下一轮基线”需要专门验证和修复。
