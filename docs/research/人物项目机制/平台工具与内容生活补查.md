## 2. Agent-Reach 是渠道适配层，不是完整社交账号管理系统

`BilibiliChannel.actions` 只注册 `search/read/hot/subtitle`。`read` 返回标题、作者、简介和统计，不代表读到了视频内容；`subtitle` 调用 `bili video --subtitle`，描述明确只取第一分 P。没有注册评论、关注、追番、发布工具。字幕读取失败会区分登录、上游异常与找不到字幕，不能统一解释成“这片没有字幕”。[^reach-bili]

`XiaoHongShuChannel.actions` 注册搜索、正文、评论，调用 OpenCLI；正文要求搜索取得的完整链接，评论响应明确附带 `content_scope=loaded_comments` 和 `exhaustive=False`。读取的是已加载评论及回复，不能声称穷尽评论区。它没有发布入口。[^reach-xhs]

一个容易忽视的账号边界：Agent-Reach 的 B 站字幕路径会尝试从已有站点登录来源复制 cookie，再调用上游凭据写入器。这不是纯无状态网页请求。未来部署必须显式绑定人物专用账号和隔离会话，不能默认继承操作者浏览器中的个人账号。[^reach-session]

## 3. 看视频与读评论已有可借鉴实现，但“看完”不能照搬

### 3.1 public-clis 的窄接口

`commands/video.py` 把视频信息、字幕、AI 摘要、评论和相关视频分别读取，再规范化输出；评论默认走 SDK，空结果/异常时尝试直接请求，相关错误可成为 warning。`client.get_video_comments` 按点赞顺序取一页，不等于全部评论。`get_followings` 是读取关注列表；`unfollow_user` 是取消关注，不应由这两个名字推断已经提供“新增关注”或“追番”。[^bcli-read]

它另有 `dynamic-post` 和 `my-dynamics`：前者解析返回的动态 ID，后者读取自己的动态，可为“提交后读回”提供实现参考。不能把纯文本动态发布推断成图文、视频或账号全管理。[^bcli-write]

### 3.2 kukemc 的素材组合更贴近人物探索

`video.watch` 一次组合：元信息、标签、章节、可得的 AI 摘要、字幕或已配置的 ASR、热评、抽样画面。默认热评 5 条、画面 9 张、正文最多 6000 字，均是覆盖范围限制。字幕/ASR 的来源需要保留；AI 摘要是平台另一个模型的总结，不应与直接取得的内容合并成同一证据。代码提醒视频文字是材料而非指令，可作为隔离外部内容的正例。[^kcli-watch]

**明确反例：** `--record` 会把 `progress` 设为整段视频的 `duration` 并上报历史；无论是否返回字幕，最后还会 `mark_seen`。抽样理解与真实完整播放不能等同。我们的适配不采用这两个标记作为“已经看完整段”的证明，也不把抽帧成功写成真实播放进度。[^kcli-history]

本轮查到的 `season` 命令管理自己的投稿合集，不是番剧追番。上述两个 CLI 均依赖 `bilibili-api-python`，后者一个写 `>=16.0`，一个固定 `17.4.2`。Nemo2011 的当前仓库已经归档并移除实现，因此供应与维护存在实际缺口；旧发行包是否仍可取得、接口在目标账号是否有效，本轮未运行验证。不能因库名熟悉就宣布可用，也不能凭仓库归档断言所有现存包立即失效。[^bcli-dep][^bapi-stop]

**未查明的能力：** 在这轮核对的入口中，没有确认新增关注、追番与公开空间可见性管理的完整读写链；未来需要正常登录页面或另一个经核查的适配，并分别验证写入与访客可见结果。未查到不等于整个开源社区不存在。

## 4. social-auto-upload 的发布证据停在哪里

小红书 CLI 有 `upload-note`、`upload-video`，输入真实文件、正文、标签、账号及可选定时时间。图文实现选择图片、填入内容、点击发布，然后等待创作者后台的成功 URL。这证明该流程观察到了发布成功页面；CLI 返回账号文件路径，没有把笔记 ID、公开链接、审核和实际可见范围组织成可靠回执。[^sau-xhs-cli][^sau-xhs-ui]

图文上传和发布处都有 `while True`：发布点击后若 3 秒未见成功 URL，就异常捕获、稍等、再次点击。对于长期运行的人物服务，这会把网络慢、平台审核、按钮变化等不同情况混在一起。需要适配为有限等待和“结果不确定→先查询”的恢复流程，不能直接移植无限重试。[^sau-xhs-ui]

B站 CLI 调 `biliup upload`；非零退出码抛错，成功则返回账号文件，并输出 `upload submitted`。这条包装层没有确认视频已审核公开，也没有保存结构化 BV/AV ID。定时提交更不能直接计为现在已经发布。[^sau-bili]

因此，两项目能减少读取与填写后台的工作，但都不能替代人物服务自己的动作记录、授权边界和发布后核对。也不能从“视频号上传”推断“朋友圈可读写”；这是不同产品入口。

## 5. 兼职模特与内容生活：目前能说什么

本轮尝试公开检索小红书兼职模特资料，检索入口无法读取；没有登录或要求提供账号。搜到的 B站作者自述包括“广州模特工作一天”“婚纱模特的一天”，索引可见作者说明和标题，但直接正文页均返回 412，未观看视频。因此这些只能作为后续访问清单，不能据此编写行业经验手册。[^model-vlogs]

可读的官方索引材料包含寄拍工作形式及兼职骗局个案：寄拍可能涉及商家寄送商品、拍摄图/视频及返还；模卡、通告等术语也出现在诈骗调查中。它们只支持“需要核实合作和素材来源”，不能用来推导收入、普遍工作流程、行业内的人际习惯，尤其不能把骗局当正常入行方式。正文重新打开时出现 403，报告仅采用搜索索引可见的官方描述，不伪称完成全文访问。[^model-context]

本轮未得到足够的一手资料来确定大陆兼职模特的普遍报价、返图周期、商业使用条件、经纪比例或聊天惯例。招聘广告属于招聘方主张，不是这些事实的可靠替代；台湾经验也不自动适用于大陆。

对“哪些身份能产生真实内容”的比较是我方产品推理，不伪装成行业研究结论：

| 候选 | 可以由工具真实完成的部分 | 不能仅凭生成内容声称发生的部分 |
| --- | --- | --- |
| 兼职模特 + 穿搭/数字造型兴趣 | 制作虚拟人物造型图、比较构图、整理作品、发布制作成果 | 真人到棚拍摄、摄影师返图、真实客户委托与报酬 |
| 摄影/修图爱好 | 对授权素材做风格试验、修图、接收真实协作文件 | 外出取景、真实接触拍摄对象 |
| 插画/设计爱好 | 可检视的原创数字作品及迭代过程 | 编造客户订单或冒称手绘过程 |
| 看番/影视兴趣 | 实际接触可得内容、评论、兴趣清单和公开讨论 | 全片观看、片中事实及全部评论的未经取得部分 |
| 烹饪/手作/旅行 | 学习资料、设计计划 | 真实制作、味觉、身体感受与到访照片 |

现阶段“兼职模特背景 + 数字造型/摄影兴趣 + 实际内容阅读”能兼顾用户偏好与可核验动作。不是把人物改成明星或把全部人生改成教程博主；线下背景的生成依据由生活专题决定，公开账号保持虚拟人物身份透明。

## 6. 对设计最有价值的结论

1. **读取成功不是体验完整。** 视频标题、字幕、抽帧、热评、播放进度是不同材料，须保留覆盖范围。
2. **提交成功不是公开完成。** 日程到点、按钮点击、进程退出、后台成功页、公开对象可见，需要区分；目标是最后能回查真实结果。
3. **现成工具也会自带人物不该继承的行为。** 自动复制操作者登录、上报全片观看、无限点击发布，均应在适配时剔除。
4. **职业背景与真实产物分开求证。** 允许虚构人物有职业，不允许生成图片就变成真实商业合作证据。
5. **上游公开生活机制可借，但外部平台事务要补。** Yuralume 的来源候选、私密过滤和完成主张校验有直接参考价值；我们新增跨平台动作状态、回查与隐私投影，不能声称这些已由上游完整实现。
