# 中文日常聊天的用词与语域调研

用途：语言与语料证据。资料和下载状态截至下列核查日期；后续采用与实验入口见 [总索引](../README.md)，不把研究建议当已选定提示词。

调研日期：2026-10-20。使用 research-zh；并行核对语言研究、中文语料和开源项目源码。本轮只研究和记录，不修改任何角色、上游核心提示词或实验模块，不调用聊天测试模型，也不安装所查项目。

## 对需求的理解

用户所说的“惯用词”，可以先理解为：一个人在某种关系和场景里，习惯选择哪些词、怎样搭配、用什么句式完成回应。词本身可能很常见，组合起来却像咨询师、客服或经过润色的文案。普通人也不是统一语言群体，目标应进一步限定为当代大陆年轻熟人之间的日常文字聊天。

因此本轮最合适的研究方向是**词汇选择和语域适切性**，并结合**常见搭配、语块及个人表达习惯**。这是一组相关概念，没有一个术语能单独包办全部问题。先前对照中，明确求安慰时仍出现工整的安慰框架；不能只把这个现象解释为句子长、关心太多或几个生僻词。相关实测仍以 [具体回应示例对照验收](../records/具体回应示例对照验收.md) 为准。

| 概念 | 通俗解释 | 本项目应检查什么 |
| --- | --- | --- |
| lexical choice / preference，词汇选择／偏好 | 有几个近义说法时，习惯挑哪个 | 对普通事物是否总换成抽象、正式的称呼 |
| register，语域 | 对谁、在什么场合说话，会影响用词和句式 | 熟人闲聊是否反复使用报告、客服或咨询场景的表达 |
| collocation，搭配；lexical bundle，词汇语块 | 词怎么组合、哪些连续说法经常出现 | 单词都普通，整段说法是否仍像精修的安慰文案 |
| lexical / stylistic alignment，词汇／风格适应 | 交谈中采用彼此容易理解的说法和相近的表达方式 | 对方说得朴素，回应是否无端切换到郑重、抽象的口吻 |

中文语块研究确实把会话与新闻分开，并同时检查频率、跨文本分布、词语关联与人工分析，不能把出现过的任意 n-gram 都视作某个人的稳定习惯。[^bundles] 词汇适应研究也区分词、结构和意义层次；相同话题不等于相同说话方式。[^alignment]

## 比通用禁词更可靠的研究经验

### 1. 模型有词汇和句法偏好，场合是否匹配同样重要

Reinhart 等比较英语中相同上下文的人类与模型续写，发现模型在不同语域中的词汇、语法和修辞分布都有偏差；扩大模型并没有消除这种差异，所测指令模型的偏差还更明显。它支持检查整体分布，但英语长续写实验不能给出中文短聊天的禁词表，也不能据此断言当前模型的具体训练原因。[^reinhart]

Juzek 与 Ward 从 Llama 的英语科学摘要续写和偏好判断实验研究词汇过度使用，提供了偏好学习可能参与形成词汇偏差的证据。其材料和模型范围很窄，不能把结果推广成所有 AI 味都由某一种训练造成。对我们有用的是比较同任务、同场景的表达频率，而非翻译其英文词表。[^overuse]

### 2. “词汇画像”比一个人的形容词标签更具体

Schaaij 等研究从个人口语转写提取高频词、词性分组和连续语块，再用同一访谈中未参与建档的后续时间窗检验稳定性。它为记录一个人具体怎么说话提供了方法。研究对象为荷兰老年人的访谈，未验证跨日、跨话题的长期稳定性或中文聊天产品效果；其样本量与时间参数不能直接变成我们的配置。[^profiles]

因此“普通、温柔、27 岁、行政”这类背景事实，不等于已经指定了个人语言习惯。这是对本项目的研究推论，不是论文验证过本项目的结论。词汇画像也不应要求模型每轮重复某个口头禅。

### 3. 要分开“找出不自然”和“改写指定问题句”

NICO 将语法、连贯和自然度分开评估。对话来自模型草稿加人工修订，并非真人聊天采录。实验中的改写任务已经指出待改句；识别任务则困难得多。可借鉴人工先定位问题、保留完整上下文再改写的方法，不能把模型自检当充分验收。研究所测为 2024 年模型。[^nico]

NICO 的最新已核版本仍写未来发布，论文未提供可验证的作者数据／代码下载入口。本次未找到确定公开可下载的版本，不能将它列为已经取得的开源语料。[^nico-version]

## 开源社区的具体做法

### QQbot：正负表达对照＋分区语句素材

`2711944586/qqbot` 固定到 `61844a4e8770a634d9dd3b4e65c25d0a541ebe81`。其风格资料按否定、肯定、承认不知道、时间表达等列出具体说法，例如否定时对照“实际上并非如此”和“不是这样”。同时提醒不要连续堆同一口癖。它是特定游戏直播群聊的语域库，其梗、反问和称呼不能直接变成普通伴侣的表达。[^qq-style]

源码中，知识库开启时，风格分区和话题分区会被检索、整理成 `knowledgeInfo`，再进入模型消息。这比只放一份永远没人读取的清单更具体；但本轮未运行它或验证语言效果。[^qq-runtime][^qq-messages]

也核到一个边界：虽有近期回复开头提取逻辑，这条路径构造的 job 却固定空 `contextMessages`。因此不能宣称其动态防复读在该路径已经起效。[^qq-runtime] 此外，词表中的时间近义词并不在所有句子中等义，不能机械全局替换。

### Ta.Skill：样本、功能词和情境一起建档

固定到 `b734e1fd0f2ce34384a213b9a7aa6e88375747c1`。它要求风格字段追溯具体样本，区分句式、功能词、情绪场景、标点和话轮习惯；还区分真实口语和打字习惯。它同时列出了包括“确实”在内的禁用表达。可借鉴的是记录结构，不是无条件接受黑名单。源码为 Markdown 提示协议，不能把每隔几轮检查的指令称为已实现的程序化调度或效果保证。[^ta]

### ATRI-skills：推荐词也需要触发条件和频率

固定到 `75824a286c04a14bcde25df9cb8dfb092c58cf7d`。其正向词表带触发情境、强度／频率限制，说明推荐词同样需要控制使用条件。但词汇强烈动漫角色化，不适合直接复制到本任务；约束写在提示中，本轮未见独立频控效果证据。[^atri]

### SillyTavern-Triggeryze：命中套话后改整段

固定到 `56a1f679a3e470c06e5dda4260386fb09fcb1ce9`。可导入 anti-slop 规则使用英文 RP 套话及正则，命中后另调模型改写所在段落，提示明确要求不要只换同义词。实际动作会改消息并保存；默认规则为空，不能说安装即启用。[^triggeryze][^triggeryze-action]

它提供的是实现思路，不是中文日常措辞标准。额外调用增加计算成本，并可能增加等待或改变原意；中文检测也不能照搬英文单词边界。本项目当前没有启用这种生成后改写，更不能把经过它改写的结果伪称原始模型回复。

## 对下一轮工作的建议

以下为本次综合研究后的方案，尚未实施或验证，不是任何来源原文提示词。

建议先建立**带语境的表达偏好表**，从已出现的具体不自然片段开始，而不预先堆一个很大的“普通词白名单”。每条至少记录：

| 字段 | 用途 |
| --- | --- |
| 原始表达与完整前后话轮 | 确保判断没有丢掉求助、玩笑、情绪或关系背景 |
| 表达完成的动作 | 是赞同、否定、接抱怨、安慰、建议还是告别 |
| 哪部分不合适 | 定位词、搭配、句式、频率或多轮姿态，不笼统写“AI 味” |
| 对照材料及来源 | 区分实际语料、项目规则、用户认可表达和研究者新编示例 |
| 更偏好的说法及保留条件 | 允许多种表达，记录原说法在何种情境仍然合适 |
| 频率与跨人分布 | 区分个人口癖、题材词和较通用的日常表达 |
| 证据等级与待测状态 | 不把源码中存在、一次顺耳或模型自评写成已验证有效 |

具体推进可以采用小规模、可追溯的流程：

1. 先人工圈出上一轮确实别扭的词语和搭配，保留上下文。明确求安慰的那轮尤其值得逐处标注，但不要先将某个普通词永久定罪。
2. 从匹配年龄、地区、关系与文字交流方式的材料找对照；电话语料和字幕只作补充。真实聊天材料应有使用授权，不自动从现有用户库采集。
3. 先修一类问题，例如抽象安慰搭配；保持事实、说话目的、亲密程度不变，不趁改词增加经历、优点或建议。
4. 将固定稿与新稿放在未参与编写的新情境中匿名对照，用户看原话；既检查自然程度，也检查是否过冷、语义变化或形成新口癖。
5. 模型扫描用于找候选，人来确认。保留每轮原始请求、原始输出和模块版本；不在同一版本里边看结果边改提示词。

最值得优先吸收的是：语域匹配、具体语块建档、样本与情境追溯，以及将不自然句的定位与改写分开验收。单词常见、禁词命中少、回复短、内容完整，都不能单独替代熟人聊天的自然度判断。
