# 核心提示词聊天对比

本目录是明确启动的本机实验工具，不属于后台生产资源，也不加入普通离线测试的真实模型调用。真实运行必须得到用户授权。运行数据、逐轮模型请求、聊天和管理员口令保存在仓库外的专用私有目录，不提交 Git。

## 本轮范围

三组各 15 轮相同预设用户消息，独立会话历史，调用项目已有的套餐后端，模型 `gpt-6.1-sol`，思考档位 `medium`。真实模型输出经过正式 `/api/conversations/:id/turn` 保存，因此管理员可以在“会话与任务 → 查看记录”阅读。

| 组别 | 原文与运行边界 |
| --- | --- |
| 当前内置米拉 | 沿用仓库原角色、人设、示例和角色引擎的完整消息组装；不是读取或克隆日常用户配置 |
| MaiBot 默认 Replyer 原文子路径 | 固定 `f01f2c22df5e0ba3cb1c5bc3b6ced5d5ec39c1cb`；直接执行原始 AST 方法体、原始模板、原默认身份与风格，私聊正常回复，空参考沿用公开 Replyer API 的默认值；没有运行 Planner、表达库、插件和输出处理，不能代表完整 MaiBot |
| 溪语主提示词原文子路径 | 固定 `06928e2dbccf438109a9eeae80086bb12f729fd3`；直接调用原 `buildSystemPrompt`，原默认角色与关系配置；没有首轮提示、情绪/事实/场景状态更新、inner OS 或输出守卫，不能代表完整溪语 |

原文件、许可证、来源和 SHA-256 位于 `maibot/`、`xiyu/`。两个原文组的宿主角色只含路由标记，没有新写的人设或规则；标记和宿主附加系统提示在传输前剔除，不送给模型。文字提示词没有新增胶水。历史适配、调用 Replyer 的时机和传输属于单独记录的运行胶水。

保留原人设意味着比较对象并非同一身份：当前组是灯塔角色，MaiBot 默认是女大学生，溪语默认带恋爱关系设定。结果可以比较说话表现，不能把差异都归因于某条文案或项目整体能力。每组仅一次运行，用户消息由脚本预设，不是自然人盲测。

### 参数和输出不作隐瞒

当前套餐适配器不传 temperature、top_p 和输出上限；三组使用相同模型和思考档位，上游采样参数仅记录，不能声称完整复现原生成参数。`system` 按既有传输契约转换为 `developer`，原内容与顺序保留；每轮保存实际 wire 请求。溪语原提示可能生成 `||` 分段符，本轮保留原始输出，没有自作主张改成气泡或删词。MaiBot 原方法对历史和目标消息进行的规范化仍照原代码执行，完整输入另存于会话记录。

## 使用

仓库根，使用 Node 24，先 `npm run build`。离线检查不读凭据、不调用模型：

```sh
node experiments/conversation-comparison/offline-test.mjs
```

得到授权后，在**不存在**的新私有目录开始一次真实运行：

```sh
node experiments/conversation-comparison/run.mjs --live --root /绝对路径/新的专用实验目录
```

入口输出随机回环 URL。管理员口令仅位于该目录的 `admin-password.txt`，不回显。唯一凭据读取者是项目已有 `openPlanCredentials`；沿用 Between 专用授权，不读取其他应用登录材料，不复制 token。锁冲突时拒绝启动，不删锁、不切换计费方式、不自动重试。

测试每次完成后立即落盘，45 次自动调用结束即停止自动生成。查看 `suite.json` 确认完成数和失败边界，不能用 HTTP 200 或流式 delta 冒充已保存回复。`transcripts.json`、`聊天记录.md` 是完整可见聊天；`evidence/*.json` 是每轮原请求、传输请求、源信息、哈希、原始回复和完成状态。

结束真实测试进程后，可不读取凭据地重新打开记录：

```sh
node experiments/conversation-comparison/run.mjs --review --root /绝对路径/已有专用实验目录
```

复查实例的服务层只允许 GET/HEAD 与管理员登录/退出，拒绝模型配置、创建会话、生成、修改和删除，不能通过切换后端发起推理。它不是正式应用的替代入口。

Ctrl+C 关闭本次进程和自己持有的锁；保留测试证据供用户查看。不要把实验数据导入日常用户目录，不把聊天、凭据或 `runtime.json` 纳入提交。失败后的目录仍保留，不为重跑而覆盖，重新测试须另建目录并确认调用范围。

## 验收重点

- 原文件哈希；原文调用链与新增胶水独立可审计。
- 原文组不混入宿主的角色设定、示例、世界书或历史后规则。
- 保存完整原始输入、输出及三组独立历史，不用摘要代替。
- 管理员阅读全文、查找、关闭回焦、加载/失败恢复、空记录和鉴权隔离。
- 用户亲自体验后决定方向；短回复、无动作描写或某次顺耳的回答都不是自然度已验收的充分证据。

## 新编的反面案例提示词对照

[普通中文聊天反面案例 v0.1](prompts/普通中文聊天反面案例-v0.1.md) 是根据公开讨论新编的独立候选模块，含十个具体情境及适用边界。它不属于任何上游原文，不替换 `maibot/`、`xiyu/`，正式应用不自动加载。来源、改编性质和组合边界见 [编写说明](../../docs/日常聊天反面案例说明.md)。原有三组聊天记录不是这个新模块的验证结果。

`negative-examples.mjs` 定义相同最小人设的两组、18 条新场景输入。基础组只含周宁的人物事实；反例组在相同事实后逐字加入整份 v0.1。两组清除宿主默认文案，保留各自完整历史，固定相同模型和思考档位；每轮原请求、实际 wire、提示词 hash 及原始回复仍写入专用私有目录。预算提高到 32768 避免长历史在进入编译器前被裁剪；现有套餐传输仍不支持温度、top_p 和输出上限，不能声称控制了随机种子或完整复现采样参数。每组只跑一次，不构成统计显著或普适有效的证明。

仅在用户授权后显式选择新套件，每次 36 次请求，没有自动重试或续跑：

```sh
node experiments/conversation-comparison/run.mjs --live --suite negative-examples --root /绝对路径/新的专用实验目录
```

默认不传 `--suite` 时仍为原有 45 次原文对比。所有套件均限制自动请求总数。完成后关闭自己启动的 live 进程，使用不读取凭据、不允许推理和业务修改的复查入口：

```sh
node experiments/conversation-comparison/run.mjs --review --suite negative-examples --root /绝对路径/已有专用实验目录
```
