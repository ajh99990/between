# Managed Qwen host contract v1 (implementation candidate)

Pinned upstream: Qwen Code v0.24.7 / TypeScript SDK 0.1.16; Apache-2.0. Breaking managed-host build, no compatibility shim.

`query({prompt, options})` requires options.sessionToolAllowlist: readonly string[]. `[]` exposes/executes no tools. Exact final runtime names only; no aliases, wildcards, auto-approval or builtin exemptions. `allowedTools` is still approval configuration, never authority to expose/execute a tool.

CLI `--session-tool-allowlist '["exact_name"]'` required. Managed CLI always operates with bare settings. Policy is immutable per Config; child Config intersects parent and child tools. Runtime registry, permissions and scheduler each check it. Missing policy throws at Config creation. Persisted session ceiling only narrows; resume/fork require saved policy and intersect it with current caller policy. Legacy sessions without policy are rejected. Use a fresh CLI process per resume/fork; in-process session switching is rejected to prevent reuse of stale runtime state.

SDK hooks: `hooks?: SDKHook[]`, `SDKHook={event, callback, matcher?, timeoutMs?}`. callback(input,{signal,toolUseId}) returns HookOutput | boolean | void. `false` blocks. Before-tool callback failure/deadline blocks. Managed runtime rejects shell/HTTP hook execution; configured SDK function hooks are the intended entrypoint. Hook registration is not tool permission.

SDK capture: `captureProviderContent?: boolean` default false; `providerCaptureMaxBytes?: number` default 16384, maximum 1048576. Every final provider SDK send emits started/finished system messages: `{type:'system',subtype:'provider_attempt',uuid:event_id,session_id,data:ProviderAttemptEvent}`. Match by `attempt_id`; de-duplicate by `event_id`. `phase=finished` contains output+usage+status; `response_complete=false` explicitly marks partial/cancelled/incomplete output. Final converted semantic request, not HTTP bytes or private model reasoning. Field capture statuses: present/disabled/redacted/oversize/unavailable. Event contains trace/span/exchange IDs; do not infer parentage by timing.

Core integration may pass ProviderAttemptOptions.onAttemptEvent/redact/storeOversize at Config construction. Oversize references are controlled IDs with expiry, never a guessed public URL. SDK consumer should consume structured events, not parse prose or log text. Capture remains explicit opt-in synthetic-only until deployment privacy/retention verification.

This file describes the implementation contract, NOT passing production gates. Tests/build/remaining gaps are reported separately. No real model, real credentials, network listener or UI verified.

Additional enforced boundaries: initialize must advertise capabilities.managed_host_contract_version === 1 or SDK initialization fails. SessionEnd hooks are unsupported and rejected explicitly. External Codex/ACP subagent executors and per-agent MCP service startup are rejected; configure approved services at the session host. Bare mode will not dispatch project/user/extension subagent definitions. Daemon managed-context execution lacking an authenticated exact policy is deny-all. Oversize reference expires in 24h; physical deletion while host is stopped requires the product retention job, not assumed by the SDK.

Provider protocols supported by this patch: OpenAI Chat Completions/Qwen-compatible pipeline, Anthropic Messages, Gemini generateContent. OpenAI Responses is explicitly rejected until instrumented. OTel exporters may be disabled: independent async context still emits attempts; zero OTel IDs are marked unmatched. attempt_index and sequence are exchange-local; attempt_id is globally unique, retry_index follows outer retryWithBackoff. Exposed provider reasoning fields may be present with content opt-in; no unavailable internal reasoning is fabricated.

Authoritative readback: initialize control response includes effective_session_tool_allowlist from the constructed Config. After Config initialization and MCP readiness, CLI emits system/host_policy with data {schema_version:1, managed_host_contract_version:1, source:'runtime_config', session_id, effective_session_tool_allowlist, registered_tools, hooks_status:'present'|'unavailable', unmanaged_hooks_blocked, sdk_hooks:[{event,matcher,name,timeout_ms}]}. Tool names come from live registry including registered lazy factories; hook entries come from actual SessionHooksManager registrations. Requested options and contract-version advertisement alone are not runtime readback.

Environment isolation: managed SDK child environment is an explicit replacement. QueryOptions.env must supply absolute HOME, QWEN_HOME and QWEN_RUNTIME_DIR; the SDK does not inherit process.env credentials. Supply needed PATH and authorized provider settings explicitly. Keep those roots private and outside model-writable cwd. Passing a blank environment does not fall back to the user's home.

Final text provenance: success and assistant wire messages can carry provider_attempt_id (the exact terminal Finished response), response_id (from that same attempt when supplied), and provider_attempt_ids (all surviving text contributors across continuation attempts). Join exchange_id through the unique attempt_id event. Structured-output or summary overrides and errors carry no fabricated terminal model ID. Missing trusted provenance remains missing and must block a product flow that requires causal proof.

SDK module identity exports SDK_VERSION='0.1.16' and MANAGED_HOST_CONTRACT_VERSION=1, asserted against package.json during release checks. Runtime CLI init still reports qwen_code_version='0.24.7'; artifact SHA256 identifies this maintained patch revision.

Additional hardening: default managed CLI session entry forces minimal settings before loading any ambient settings and skips home .env bootstrap. SDK TypeScript source executable paths are rejected; use the built JavaScript/native CLI, avoiding ambient tsx helper subprocesses. chatRecording defaults false and is a typed option; enable explicitly only when transcript retention is approved. With chatRecording:false, native transcript resume may be unavailable and must not be claimed successful.
