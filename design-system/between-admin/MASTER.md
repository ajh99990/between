# Between 管理端设计规范

本文件描述当前经典后台布局。技术栈为 Ant Design Pro / ProComponents、React、TypeScript、Umi Max、Tailwind；结构调整不改变界面设计或 API 含义。实现位于 `apps/admin`，2026-10-13 的设计来源与历史验收记录见 [后台经典布局重写与验收](../../docs/后台经典布局重写与验收.md)。

## 用户任务与内容

管理员以内容为中心：浏览角色或世界书，完整阅读设定及来源，修改明确字段，确认对新会话的影响，保存并重新读取。角色库、世界书、模型与提示词、会话与任务、用户与全局、素材与诊断是六个固定入口。用户聊天正文不作为管理员配置页面或遥测内容。

角色的 11 个文本字段、每个世界书条目的正文与扩展配置均完整可读。列表可以提供摘要；全文视图保持原文，并提供目录、搜索、跳转和来源。HTML 内容按纯文本显示，不能执行脚本或自动加载外部资源。角色设定、世界书、默认 Persona 与编译提示仅由服务端组装，不能进入普通用户状态响应、可见消息或语音输出。

## 布局与视觉

桌面固定侧栏 216px、顶部工具栏 56px、工作区边距 24px，主要控件高度 36px。800px 以下使用可关闭的抽屉导航；600px 以下阅读目录单列。表格只在自身区域横向滚动，不带动整页。取消营销标语、装饰指标和重复功能介绍，优先显示业务内容及主要操作。

沿用深蓝画布 `#080d1b`、内容面 `#131c32`、浮层 `#19243c`、正文 `#eef3ff`、次文 `#b0bdd4` 与蓝紫、冷青动作和焦点颜色。内容卡圆角 14px、细边框；危险操作使用明确的 danger 语义。系统字体，无远程字体依赖。正文 16px / 1.85，长文限制行宽但不截断；保留换行，长 URL 可以折行。

Ant Design 控件负责表单、确认、导航和状态，Tailwind 负责布局与阅读排版，不开启 Preflight。状态用文字与图标共同表达，不能只靠颜色。

## 编辑与异常恢复

阅读与编辑分开。编辑抽屉最大 1040px；长字段可展开为最大 1120px / 60vh 文本编辑区。展开输入直接进入受控表单草稿；“应用”返回表单，最终保存仍需确认。放弃展开修改时恢复该字段原值，并保护未保存草稿。

保存基于打开编辑器时的版本快照。409 冲突不覆盖服务端，失败保留草稿；提交后刷新失败须明确提示，避免重复提交。重复操作有提交锁；取消、离开或刷新保护脏编辑。401 返回登录，重新登录后可恢复工作。保留来源与未知字段，世界书扩展 JSON 必须是对象，不能覆盖 UID 或常用字段。

删除、停用、暂停、断开等操作说明真实作用范围，并提供确认或取消。管理员权限由 API 鉴权、CSRF 与 Origin 检查落实。模型“已配置”、套餐授权元数据存在和真实推理成功分别呈现；离线模拟状态不能显示为真实模型验证。

## 验收要求

检查 1440、1024、768、375px 下的六个页面、全文阅读及编辑。使用许可社区素材和虚构边界数据，覆盖长中文、长 token、多条目、搜索空结果、加载、网络失败、登录过期、保存失败与版本冲突。检查焦点可见、键盘返回、Tab 范围、缩放、reduced-motion、抽屉关闭和整页横向溢出。

测试结果记录代码版本、执行命令和实际观察，分别说明真实接口、响应模拟与未覆盖范围。类型检查、DOM 断言或截图存在不能代替像素检查；离线合成回复不能作为模型质量结论。浏览器测试证据写入忽略目录 `artifacts/browser/admin`。
